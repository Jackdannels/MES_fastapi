# 外部系统连接状态与 LIMS 通讯保障

## 当前策略

已实施，按用户要求**暂用 10 秒重试，不使用 10 分钟**。按重置后的新数据基线验收，不提供旧数据迁移或历史账本补建。

| 阶段 | 行为 |
| --- | --- |
| 正常 | 每 60 秒双向应用检测和消息对账；业务回调持续发送 |
| 首次通讯/同步失败 | 立即普通告警，首次失败不算重试 |
| 重试 | 每次失败确认后等待 10 秒；第三次重试仍失败升级严重告警 |
| 升级后 | 继续每 10 秒尝试，直到恢复，不静默放弃 |
| 链路恢复 | 补传并对账；全部检查通过才清除活动告警，历史保留 |

请求本身的耗时另计。故障期间“检测 / 补传”不会提前截止时间、重置次数或绕过调度。确认告警仅记录“已知悉”，不清除故障或停止重试。

## 双向应用检查

MES 后台通过 HTTP POST 发起携带随机 `check_id`、版本号的探测。LIMS 模拟器返回 HTTP 应答，并经 RabbitMQ 独立临时路由向该 MES 实例发送同 ID 探测消息。两个方向均成功才算链路畅通。

- 探测消息不进入任务或试验完成业务记录。
- 独立临时队列隔离实例；迟到或错 ID 应答不能确认本轮。
- 任务使用 MySQL advisory lock，多个 MES 进程不会并发跑同一轮。
- 重试截止时间和计数在 I/O 前落盘，正常重启不清零。
- 启用通讯保障时，RabbitMQ 启动失败不阻止 MES 启动，后台继续告警、重试；就绪检查仍返回异常。

## 持久化与消息补传

MES 在现有 MySQL `app_storage_snapshot` 表保存私有 `lims.communication.*` 状态、控制请求、发送账本和接收账本。短更新用行锁及事务，调度用数据库互斥锁。无需新增表或结构迁移；这些记录不是前端可编辑的业务快照。

模拟器在自己的 `communication.sqlite3` 中保存下发信封、消息 ID、内容摘要、尝试次数、截止时间和确认结果。先持久化再发布；失败返回 `publish_status=queued`，成功发布返回 `published`。队列由 MES 对账任务驱动补传，发布成功不代表 MES 已处理成功。

双方按原消息 ID 和规范化 JSON 的 SHA-256 摘要逐条对账，分批处理（最多 100 条），持久化检查点。缺失记录沿用原 ID 和信封重放；同 ID 不同内容保留异常、阻止“同步正常”。周期对账重新扫描账本，能发现中间缺口，不仅比较总数或最后时间。

- MES → LIMS：复用持久化 outbox 和 SQLite inbox；HTTP 成功后先记录发送历史，再移出 outbox。落盘后丢 ACK 可幂等重传。
- LIMS → MES：模拟器持久化发布账本，MES 处理后保存确认账本；确认过的消息重投不再产生任务业务副作用。
- 数据库或账本不可用时显示未确认/存储异常，不编造成功。
- 本次为任务、回执、完成结果的**消息级续传**，不含大文件链接的分片下载或 HTTP Range 续传。
- 普通服务重启保留账本；显式系统重置与普通重启不同。使用新基线时，两端通讯账本和模拟器队列应属于同一轮测试，不要只清理一端业务数据后继续复用旧消息身份。本次未主动清理现有数据。

## 页面

模拟器 `/#communication` 新增“通讯保障”：双向链路、保障阶段、告警等级、最近检测/成功时间、故障开始、重试次数、倒计时、检查点、同步差异、待补传、最近 100 条下发和告警历史。

操作：刷新、检测/补传、确认已知悉；故障注入包括 HTTP 503、HTTP 超时、阻断 RabbitMQ 发送、下一条通知落盘后丢确认、下一条通知模拟遗漏落盘、恢复链路。注入条件持久化，两个“下一条”选项仅消费一次。“恢复”不伪造 MES 检测结果，不删除实际接收记录，也不影响上位机 MQTT。

页面只观察后台：关闭浏览器、关闭模拟器后 MES 仍可告警。页面每 2 秒读取；失败或状态过期不继续显示旧健康状态。按 UI/UX 规则使用文字与颜色共同表达状态，按钮有等待/失败反馈，延续现有深色样式。

MES 侧栏分别显示 LIMS、上位机系统，并显示 LIMS 普通/严重告警：

- 所有中控页面标题栏右侧采用统一的“严重告警 1”入口，仅严重告警显示。点击打开 **680px 最大宽度的居中弹窗**，展示真实原因、北京时间、持续时间、重试与双向链路、最近事件；不跳转当前页面。入口与侧栏共用状态轮询。
- 弹窗支持 Escape、遮罩关闭、Tab 焦点循环及关闭后焦点返回，适配明暗主题和小屏。确认已知悉使用已登录中控会话，不向浏览器下发 LIMS Token；只排队确认，不清除故障。真实恢复后入口消失，已打开的弹窗显示“通讯已恢复”；读取失败显示未确认而不是假恢复。

- 严重告警在 MES 侧栏和模拟器告警卡片使用红色边框慢闪（1.6 秒周期），文字不闪灭；普通告警不闪。已知悉不停止严重提醒，恢复后停止。系统开启“减少动态效果”时改为静态红色强调。

- LIMS 启用保障时使用后台持久化状态；未启用时可用 `LIMS_HEALTH_URL` 做只读对端检查，但不能代表同步成功。
- 上位机要求 MES MQTT 接收链路在线及实际遥测新鲜。只覆盖已观测试验间；默认 5 秒延迟、15 秒离线。保持二室夹具本地模拟例外。

## 配置与生效

```dotenv
LIMS_HTTP_CALLBACK_URL=http://127.0.0.1:8900/api/mes/events
LIMS_COMMUNICATION_ENABLED=true
LIMS_COMMUNICATION_URL=
LIMS_COMMUNICATION_INTERVAL_SECONDS=60
LIMS_COMMUNICATION_RETRY_SECONDS=10
LIMS_MES_BASE_URL=http://127.0.0.1:8000
```

`LIMS_COMMUNICATION_URL` 空时从回调地址推导同目录 `/communication`，例如 `/api/mes/communication`。正式 LIMS/网关需实现此协议。`LIMS_MES_BASE_URL` 是模拟器访问 MES 的地址，启动脚本按后端端口设置。

MES 和模拟器共用 `LIMS_HTTP_TOKEN`：空值只接受本机服务调用；远端配置相同 Token 并使用 HTTPS。HTTP 禁止重定向。模拟器操作和故障注入仅允许本机同源请求；开发工具不要公开暴露。

**同时重启 MES 后端和 LIMS 模拟器，再刷新页面。**生产前端需重新构建发布。未来恢复十分钟策略时将 MES 重试配置改为 `600`，本次不作此修改。

接口：MES `GET/POST /api/system/lims-communication`；模拟器 `POST /api/mes/communication/{probe,reconcile,resume}`，只读页面聚合 `GET /api/communication`，本机操作 `/api/communication/{action,faults}`。

当前为站内告警，未接入短信、邮件等外部通知。验收覆盖十秒重试、三次升级、重启保留、跨实例互斥、鉴权、内容冲突、缺口补传、丢 ACK 幂等及页面交互；不修改实验控制工作流。
