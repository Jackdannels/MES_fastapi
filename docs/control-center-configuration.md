# 控制中心系统配置

控制中心左侧 **系统配置** 集中修改数据库连接、RabbitMQ / AMQP、MQTT、HTTP / LIMS、报告备份及登录等重要参数。每项显示中文名称、**文件中的值**和**中文释义**；原始配置键放在选中项详情中，便于与配置文件对应。

默认只展示实际文件中已有的重要配置。勾选 **显示未配置项** 后，可补充连接所需的重要参数；未设置的项显示“未配置”，编辑框留空，不预填代码默认值。文件中明确设置的空字符串显示“（空值）”，与未配置区分。读取、筛选和切换页面不会补写参数。

支持按分组筛选，以及按中文名称、用途和原始配置键搜索。密码默认隐藏；布尔值用“启用（true）”“停用（false）”显示，保存时仍写入原配置格式。

## 三种部署方式

| 部署方式 | 实际写入位置 |
| --- | --- |
| 本机开发 | 项目根目录 `.env` |
| Docker 便携部署 | `mes-desktop-tools.json` 中 `deploymentDirectory`、`environmentFile` 指向的环境文件 |
| Windows 原生服务 | `mes-desktop-tools.json` 中 `nativeConfig` 指向的 JSON 的 `environment` 对象 |

页面顶部显示实际文件路径。配置页不需要先连接 API，因此服务因连接参数错误无法启动时也能修正配置。Docker 的监听端口、公开访问地址、镜像和部署身份由部署工具同时更新相关服务及客户端地址，不列入此精简页面。

原生控制中心启动时请求管理员权限，以读取和保存受保护的配置；原有配置目录的 ACL 保留。更新原生安装时，请在管理员 PowerShell 中运行配套更新脚本。

页面仅开放维护日常连接所需的常用项。连接池、性能监控、历史保留策略、调试、自动建表、迁移账号、会话签名密钥、达梦占位和模拟器内部开关等不在页面展示；已有内容继续保留在原配置文件中。

Docker 只开放当前部署的 Compose 文件确实引用的环境变量，已有但未接入的常用项标为只读。Docker 使用 `MYSQL_API_USER`、`MYSQL_API_PASSWORD`、`MES_LOGIN_*`、`MES_FRONTEND_ORIGINS` 等部署键时，显示并编辑这些实际键对应的值，不用后端默认值代替。原生版仍编辑 `nativeConfig.environment`，不强制迁移为 `.env`。

## 保存与生效

- **保存配置**：先校验修改项，再保存文件；运行中的进程继续使用原来的配置，重启后读取新值。
- **保存并重启**：保存成功后，进入控制中心既有的重启确认流程。取消重启仍保留已保存的文件。
- **重新读取** / F5：重新加载文件；有未保存修改时先确认是否丢弃。切换页面保留草稿。
- 原文件在同目录自动备份为 `原文件名.bak.时间戳-标识`，再以原子替换方式写入。保存结果显示备份路径；恢复时停止服务，将需要的备份复制回页面显示的配置路径，再启动系统。
- 文件被其他程序修改后，保存会拒绝覆盖，需重新读取并编辑。

密码、令牌、会话密钥和含凭据的 AMQP 地址默认隐藏。点“显示密码”仅显示当前选中的值。备份包含原有凭据，应与原配置保存在同样受限的目录。

端口、数字、布尔值、HTTP(S) 地址、AMQP 地址和相关路径在保存前校验。只保存实际改动的字段；`.env` 的其他内容、注释和多行值保留，原生 JSON 的服务身份、监听端口、数据目录和其他对象保留。

## 连接参数与部署参数

连接密码必须与目标 MySQL / RabbitMQ 服务上的账号一致。此页面修改 MES 客户端的配置，不执行服务端改密、建用户、授权、数据迁移或删除数据。原生安装器管理的服务监听端口、Caddy 配置、Windows 服务以及桌面客户端地址仍由部署工具管理。

Docker 中 `MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_PASSWORD` 可覆盖应用连接，未配置时继续使用原来的内置 MySQL；未设置独立连接账号时，页面显示环境文件中已有的 `MYSQL_API_USER`、`MYSQL_API_PASSWORD`。已有数据卷不会因为编辑连接密码而自动更改其中的账号密码。原生自带的备份/还原工具仍面向其内置数据库；应用改连外部数据库后，应使用目标数据库对应的备份工具。

Docker 中 `RABBITMQ_URL` 可覆盖 AMQP 连接；MQTT 的主机、端口、用户名、密码和主题前缀可单独配置。新部署文件把相应参数同时传给 API 与配套模拟器，保证连接与路由一致。本机开发启动器也只向 LIMS 模拟器传入其需要的连接项，不从共享文件复制数据库或管理员凭据。

现有安装升级时，需要同时更新控制中心 EXE 和本轮配套部署文件。Docker 需更新 `compose.portable.yml`、`compose.portable.simulators.yml`；原生服务需更新 `native/service_entry.py`。本轮更新包的 `Update-ControlCenter.ps1` 会校验、备份并更新这些文件。仅替换旧 EXE 不会为旧 Compose 增加新的环境变量入口。配置文件与业务数据继续使用原目录中的文件。

更改环境变量仍遵循对应启动方式的优先级：本机 `run_local.py` 使用 `.env` 覆盖继承值；Docker Compose 的进程环境可能覆盖 `--env-file`；原生服务使用 `nativeConfig.environment`。页面展示的是文件配置，不代表正在运行的连接已切换。

本机 `.env` 中 `${...}` 会被 python-dotenv 展开，编辑器拒绝将其当作字面值保存；需要这类字面密码时使用进程环境变量。Docker 保存时自动处理 `$`、引号与反斜杠。

## 维护字段目录

新增或修改 `Settings` 字段、Compose 环境变量入口后，执行：

```powershell
.venv/Scripts/python.exe scripts/generate_control_center_schema.py
```

完整字段目录用于校验，页面展示范围由生成脚本中的 `IMPORTANT`、`DOCKER_FIELDS` 控制，每个展示项必须提供中文名称与用途说明。更新后的目录嵌入 EXE，不依赖目标机器安装 Python，也不需要单独分发目录文件。`tests/core/test_control_center_configuration.py` 检查字段覆盖、目录一致性、文件写入、精简页面、中文释义及真实 Compose 参数解析。

实验业务规则不在此功能中修改：所有实验室的实验准备、开始、结束仍使用 MQTT；高低温湿热二室的本地装样与夹具就绪例外保持原样。
