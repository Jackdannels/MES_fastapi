# 第三阶段 A：5 用户容量基线

测试日期：2026-07-24  
测试环境：本机生产模式，MySQL 后端，MQTT 与 RabbitMQ/LIMS 已连接  
业务数据：20 个任务、169 个样品

## 验收范围

- 5 个虚拟用户持续 60 秒，以 0.2 秒思考时间轮询健康检查、总览、样品、接驳区、可视化和 MQTT 状态接口。
- 实时环境仅执行只读请求，不修改现有任务、样品、托盘或实验数据。
- 写冲突、MQTT 和 hostless 流程使用隔离测试数据验证。
- 读取接口 P95 验收线为 500ms，请求错误率验收线为 0。

## 隔离回归

- 第三阶段探针、任务、接驳区、MQTT 与实验室相关测试：284 项通过。
- 同一托盘并发出库只有一个请求成功。
- 任务编辑、接驳操作与实验室进度并发时不会回滚后提交状态。
- 高低温湿热二室继续使用 hostless mock；其他实验室保持 MQTT 路径。

## 结论与触发条件

当前版本通过 5 用户容量验收，可支持 4～5 个用户的日常并发使用。出现以下任一情况时重新执行探针并评估第三阶段 B：

- 读取接口 P95 持续超过 500ms；
- 写操作 P95 持续超过 1 秒；
- 出现 5xx、锁等待、状态覆盖或重复业务动作；
- 同时活跃用户增长到 10～20 人；
- 准备启用多 Uvicorn worker 或多台后端服务。

重复执行命令：

```powershell
rtk proxy .\.venv\Scripts\python.exe scripts\stage3a_load_probe.py --users 5 --duration 60 --think-time 0.2 --p95-limit-ms 500
```
