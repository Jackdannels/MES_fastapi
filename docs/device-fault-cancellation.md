# 设备故障取消本次运行

设备页 → 维保计划 → 维修 → 填写设备故障原因 → 重新排程。

维修确认会按试验间的原运行批次关联托盘和样品，包括盐雾暂停后仍在外观检测间的托盘，不以样品当前位置代替原设备归属。确认框列出托盘编号、样品编号与实际位置，提供“取消后重新排程”和“设为实验已完成”两个既有处理选项；同任务同试验的其他批次托盘不混入本次处理。

此操作与盐雾暂停/停止、霉菌专用取消独立。设备立即进入维修；样品和运行状态在上位机确认前不释放。MES 不提供离线强制取消。

## MQTT

MES 使用原 `commands/experiment-end-request`，新增 `end_mode=device_fault_cancel`，包含 `task_code`、`experiment_code`、`lab_code`、`run_no`、`cancel_reason`、`cancel_request_id`。

原排程编号及排程快照仅保存在 MES 内部，用于取消确认及报告归档，不发送给上位机。

上位机安全停止当前运行后，向 `events/experiment-ended` 原样返回 `end_mode`、`cancel_request_id`、`run_no` 和实验室标识。不能用普通结束回执代替故障取消确认。高低温湿热二室仍仅安装/夹具就绪为本地例外，取消确认使用 MQTT。

未收到确认时保留运行和样品位置，设备不可开始新试验。发布失败可重试；已有待确认请求时返回原请求标识，不重复下发。故障取消请求不因普通控制命令超时而自动转为完成。

## 确认后

- 当前批次及托盘显示“设备故障试验取消”，保留开始/结束时间、原运行编号、原因和操作人。
- 原试验待排程，不算正常完成；新的试验运行不能覆盖旧批次。已完成轴向保留；当前未完成轴向取消。
- 只释放当前有效排程；同设备后续排程保留并列为待处理冲突。
- 样品位置不回滚。允许按下一有效排程进行比对，或扫码进入普通暂存间。盐雾、霉菌、高低温湿热还可进入外观检测间。
- 原流程保留故障取消节点，不替换为正常完成节点。

## 盐雾中途外观检查期间维修

- 盐雾运行处于“实验暂停”也会进入维修处理选择，不再被漏判为空闲无运行。
- 选择“取消后重新排程”：沿用设备故障取消MQTT链，确认前不释放托盘；确认后原试验待排程、原运行保留“设备故障试验取消”。已在外观间扫码入库的托盘结束中途检查阶段并保留外观间存放状态，可出库送普通暂存间或按下一有效排程派送。未实际进入外观间的托盘不补造外观入库。
- 选择“设为实验已完成”：沿用既有维修完成处理，原运行与试验完成；已经在外观间的托盘转为实验后外观存放并保留实际位置，可出库送实验后暂存间，或按后续有效排程派送。
- 本次运行的处理结果与托盘当前存放状态分开保存；搬运、出库、入库后流程图跟随实际操作继续，不要求先搬回故障试验间。

## 实验间流程监控退场规则

故障取消删除原排程后，原运行与本任务本托盘的run-tray取消事实仍作为历史依据。托盘实际仍在原实验间时，流程监控保留故障取消节点、当前所在实验间和“待转运”备注，并显示待转运托盘数量。

- 待转运只是显示备注，不新增业务状态、操作步骤或排程占用；已取消运行不重新开始计时。
- 只新增下一次排程、修改目标实验间，不等于实际转运，不能把驻留托盘从原室提前移走。
- 实际扫码出库、转运历史、入库或更新的运行关系出现后，旧室按逐托盘事实退场；缓存旧样品位置不能使已转出的托盘重新出现。
- 同一样品多盘时，一盘的汇总位置更新不代表其未移动的兄弟托盘也离开；相同盘号跨任务不能借用彼此的记录。
- 同室新运行已开始时显示新运行，旧取消仍作为历史节点，不带待转运备注。
- 没有确认运行和run-tray证据的客户端“设备故障试验取消”字符串，不能单独建立驻留显示。

## 数据归档与恢复

已收到的 `experiment-result` 绑定原 `run_no` 保存，故障取消报告注明非正常完成、数据完整性、取消原因及各轴向记录。未收到结果时注明待补齐，不生成合格/不合格结论。迟到结果仍补入原批次。

取消状态与归档待办一并保存。报告生成失败或进程中断后，试验数据页的失败列表可重试归档；文件失败不恢复已经安全停止的运行。归档待办不混入排程异常列表。

## 验证

专项测试位于 `tests/api/test_device_fault_cancellation.py` 和 `frontend/src/modules/samples/deviceFaultCancellation.test.js`，覆盖 MQTT 确认、重复请求、状态保留、多托盘/轴向、下一试验与入出库、旧运行隔离、结果补传与归档重试。测试使用隔离数据，不连接实际实验设备。
