# 盐雾中途外观检查后的恢复流程显示

盐雾暂停、外观检测返回及恢复准备都属于同一次原运行。中控托盘详情与实验室可视化共用生产托盘流程模型，不增加“等待恢复实验”流程节点。

- 后端已经使用“等待恢复实验”作为中途外观检测返回后的托盘状态；前端保留识别该值，不按位置误判成普通实验室到达，也不回退为样品运输中。
- 该值不加入人工可选状态列表。恢复准备仍沿用送至盐雾试验室、重新比对、安装、夹具确认及准备就绪。
- 暂停恢复只重置本次盐雾需要重新执行的准备步骤。到货和暂存时间按本任务、本托盘的实际流转记录或仓储事件显示。
- 可选暂存节点沿用普通流程的进度判定。托盘已越过该阶段时，缺少实际时间的节点显示为绿色推导节点，时间栏显示 `-`。实际暂存记录通过原转运段校验后显示对应时间。
- 前序实验完成后直接扫码入暂存间，可以只有入库记录而没有独立派送记录。当前转运段的真实入库记录同时证明前置“送至暂存间”已完成；该派送节点保留绿色推断状态，时间仍为 `-`，不借用入库时间。
- 过滤其他任务、其他托盘、当前暂停以后的记录；多试验中上一个已完成试验之前的暂存记录不用于填充当前盐雾的转运段。
- 暂存证据截止于原盐雾运行开始之前的实际派送；没有派送时间时以原运行开始时间为上界，不能使用中途外观检测返回或后续恢复阶段的新记录填充原转运段。
- 多次暂停时使用当前运行的最新暂停上下文，保留此前真实暂存时间；恢复运行后也使用相同历史判断。

回归位于frontend/src/modules/samples/saltSprayResumeHistory.test.js，覆盖无暂存历史、真实历史、仓储事件、缺失时间、多次暂停、多托盘、跨任务和多试验，以及生产组件渲染。直接入库场景覆盖暂停前后、恢复准备、恢复运行、原转运段时间边界和真实派送时间优先。

## 盐雾提前结束的唯一处理方式

- 当前项目只支持正常提前完成：`POST /api/mq/laboratory/stop-request` 的 `termination_type` 固定为 `completion_criteria`，字段与 MQTT topic 不变。
- MES 下发 `experiment-stop-request`，匹配的 `experiment-stopped` 确认后执行正常完成，已在外观间的托盘按实验后外观存放继续流转。
- 旧 `abnormal` 分支已删除：HTTP 请求返回 422；绕过 HTTP 的发布调用、旧待确认命令以及带异常停止类型的 MQTT 确认也不能创建该状态。上位机模拟器不再自动或手动发送此类型。
- 设备故障仍从维修入口选择“取消后重新排程”或“设为实验已完成”；霉菌专用取消保持原流程。
- 已存在的历史异常终止记录不批量删除、不改判正常完成；保留拒绝迟到正常完成的只读保护，不能再通过业务接口创建异常提前终止。
