# MES 控制中心 v2.5：局域网自动配置与启动优化

本文保留 v2.5 发布记录。当前升级入口见 [MES 控制中心 v2.7](control-center-v2.7.md)。

## 已迁移 PC 的升级

关闭旧控制中心，将整个更新文件夹复制到 MES 主机，在此文件夹打开 PowerShell 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Update-ControlCenter.ps1 `
  -DesktopToolsDirectory "C:\Users\Administrator\Desktop\MES_Docker迁移交付_20261019-r1\桌面工具"
```

脚本保留原 `mes-desktop-tools.json`，备份并替换控制中心及所需脚本，更新 Docker release 中的两个启动脚本，并在桌面创建 **MES控制中心_v2.5_Docker版** 快捷方式。旧文件备份在原桌面工具目录的 `control-center-backup-日期-时间` 中。原生安装可用同一更新脚本，选择原生桌面工具目录，生成对应原生版快捷方式；原生模式不修改 Docker 配置。

更新不会在复制文件时重启服务。Docker 启动逻辑、压缩配置和地址配置在下次“启动系统”或“重启系统”时应用。首次应用可能重建配置发生变化的容器，之后常规关闭使用 stop 保留容器。完整安装器旧副本未随此补丁重制。

## 默认自动提供局域网地址

Docker portable 默认 `MES_NETWORK_MODE=auto`，启动时自动：

1. 检测当前物理有线 / Wi-Fi IPv4，优先带默认网关的有线连接，排除常见虚拟网卡、回环和 169.254 地址。
2. 将 MES Web 监听设为 `0.0.0.0`，自动填写 `MES_PUBLIC_URL` 与各有效主机地址的 `MES_FRONTEND_ORIGINS`。原环境文件发生变化前会产生同目录带时间的备份，保留其他配置及凭据。
3. 管理员运行时添加仅适用于专用网络、本地子网的 Web 防火墙规则。普通用户没有权限时日志提示以管理员运行一次；防火墙、交换机和跨网段路由仍需现场验证。
4. 控制中心首页和“关于与访问地址”读取真实 Web 容器映射，并显示当前主机地址。只有主机上的 MES 识别接口响应通过，才标为主机访问通过；这仍需另一台电脑验证。

如电脑未连接局域网，保留本机访问并显示无有效网卡；联网后重新启动服务或刷新地址。更换 IP 后使用“重启系统”更新公开地址和 Origins，工作站需要使用新地址。

需要保留专用域名、HTTPS 网关或人工监听配置时，显式设置 `MES_NETWORK_MODE=manual`。多网卡可以用 `MES_LAN_IP=实际主机IPv4` 指定首选地址，必须是当前启用的物理网卡地址。

只有 Web 公开给局域网，数据库、API 和两个模拟器管理端口继续按原配置提供主机入口。

## 启动与响应优化

- 控制中心启动直接读取已配置的连接，异步刷新服务与地址，不在界面构建时扫描整个网段。
- Docker 引擎未运行时，“启动系统”会尝试启动本机 Docker Desktop，并等待引擎就绪；限时 180 秒，失败后给出错误。
- 常规“关闭系统”使用 Compose stop，保留容器和网络，减少后续重建。
- Docker Engine 25+、Compose 2.20.2+ 启动期间每秒检查健康状态；RabbitMQ 同时检查 AMQP 与 MQTT 监听，避免 Erlang ping 已通但业务端口未就绪时过早启动 API。迁移顺序和常规检查间隔保持原设计。较旧版本跳过快速启动检查配置。
- Web 增加 Nginx 静态资源压缩，作用于 HTML / JS / CSS / SVG；JSON API 原有压缩继续由后端负责，SSE 流不列入此配置。

这些部署优化不依赖重建业务镜像。生成的启动覆盖配置和压缩文件保存在 release 的 `.tmp` 中，启动命令仍使用原镜像版本和数据卷。生产业务中是否还存在慢 SQL、CPU 饱和、内存压力或长请求，需要按实际负载继续测量，不能由启动耗时推断。

## 使用桌面图标

当前开发机桌面直接生成 `MES控制中心_v2.5.exe`，用于当前项目开发环境测试：管理 `8000 / 5173 / 8900 / 8899` 服务，通过当前项目的 `scripts/mes-service-control.ps1` 控制服务。该入口不依赖 Docker，也不要求原生离线安装包。

Docker 更新包用于已经迁移的 PC，执行本说明开头的升级脚本会读取那台 PC 的原连接配置并生成对应快捷方式。开发环境 EXE 已绑定当前项目路径，迁移它到其他 PC 需按那台 PC 的项目路径重新构建。

验证记录与本机启动/压缩对比保存在本文件夹的 verification 中。跨 PC、防火墙及操作系统重启后的启动仍需现场验收。

## 本机对比结果与范围

使用相同的已缓存业务镜像、初始化过的空数据库和独立 Compose 项目进行对比，Docker 引擎已运行：

| 项目 | 原配置 | v2.5 |
|---|---:|---:|
| 保留容器后再启动 | 23.509 秒（1 次） | 12.453、14.176 秒（2 次） |
| 重新创建容器启动 | 24.730 秒（1 次） | 未作对应重复测量 |
| 入口 JS 传输量 | 203,873 字节 | 71,903 字节 |

入口 JS 解压后的 SHA-256 一致，传输量减少约 64.7%。两次优化后的重复启动 API 均没有发生崩溃重启。自动网络配置应用后，主机物理 IPv4 地址上的 MES 识别接口、登录和压缩资源请求通过；未测试另一台 PC。

本机额外的短连接请求采样遇到 Windows 临时端口压力（约 18,000 个 TIME_WAIT，主要指向外部 HTTP 服务），因此未给出生产 API 响应提速百分比，也未更改操作系统端口参数或其他程序。当前测量不能代表目标 PC、系统冷启动、真实业务数据量或并发负载。
