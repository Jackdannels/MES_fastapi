# 过程管控按实验维度开始实验设计

## 背景

当前试验过程管控页把“开始实验”错误地按整任务托盘集合处理，导致：

- 同任务其他实验的托盘被算进“剩余托盘”
- 任务详情里显示了不属于当前实验室当前目标实验的托盘
- 只要任务内存在准备就绪托盘，就可能误允许开始实验
- 开始实验没有二次确认弹窗，无法明确展示本次真正要启动的托盘和样品

## 目标

- 过程管控卡片默认显示实验室最近排程的任务
- 查看任务时可切换到该实验室后续任务，卡片同步跟随切换
- “开始实验”只针对“当前选中任务 + 当前实验室对应实验”下已经达到“实验准备就绪”的托盘
- 其他实验、其他实验室的托盘不参与当前实验的可启动/剩余统计
- 开始实验前弹窗确认，展示任务号、实验名、托盘号、样品编号和当前状态

## 设计

### 任务选择

- 每个实验室维护独立的当前选中任务号
- 默认任务取该实验室最近排程
- 查看任务弹窗列出该实验室相关排程任务，切换后立即刷新卡片、详情和开始实验上下文

### 实验维度托盘作用域

- 当前实验作用域由“当前选中任务 + 当前实验室当前排程匹配的实验编码”决定
- 仅该作用域内的托盘参与：
  - 可启动托盘计算
  - 剩余托盘计算
  - 当前实验托盘明细
- 若当前实验没有显式 `experiment_trays` 映射，可回退到该任务在该实验室排程对应实验的托盘集合推导

### 开始实验规则

- 仅状态为 `实验准备就绪` 的托盘可进入本次开始实验弹窗
- 存在至少一个准备就绪托盘时允许打开弹窗
- 确认后只将弹窗中的托盘和对应样品写成 `实验进行中`
- 不改写同任务其他实验托盘
- 写回后继续派发 `mes:samples-updated`

### UI

- 过程卡片的“剩余托盘/可启动托盘”文案改成实验维度
- 新增开始实验确认弹窗
- 弹窗内容：
  - 任务号
  - 实验名
  - 托盘编号
  - 样品编号列表
  - 当前状态（实验准备就绪）

## 验证

- 过程卡片仅统计当前任务当前实验托盘
- 切换任务后卡片同步切换
- 未准备就绪托盘不能开始实验
- 开始实验弹窗仅列出当前实验下准备就绪托盘
- 确认后仅这些托盘变为 `实验进行中`
