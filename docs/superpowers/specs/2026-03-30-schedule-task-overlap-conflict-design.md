# 排程任务内已排程可视化与托盘冲突确认设计

## 背景

当前排程模块已经支持：

1. 按任务、实验、实验室和时间创建排程。
2. 在甘特图中查看当前实验室的占用情况。
3. 在冲突列表中查看已有排程冲突。

但多实验任务进入连续排程时，现有页面仍有两个明显缺口：

1. 当同一任务的第一个实验已经排程后，排第二个实验时，甘特图只能看到当前实验室视角，无法直接看到该任务其他实验已经占用的时间段。
2. 当多个实验对同一批托盘发生时间重叠时，系统缺少面向排程前的分级提示，排程员无法在提交前明确知道是“部分托盘冲突”还是“全部托盘冲突”。

## 目标

本轮只增强排程页的任务内排程可视化和提交前确认，不改变最终排程写入规则：

1. 当用户选择任务和实验后，甘特图除显示当前实验室排程外，还显示该任务已存在的正式实验排程信息。
2. 当新排程与当前任务其他实验在时间上重叠时，系统按托盘交集分成 `部分冲突` 和 `完全冲突` 两类。
3. 两类冲突都通过确认弹窗提示，不自动拆分托盘，不自动调整时间。
4. 用户点击 `确认排程` 后，仍按原定任务、实验、托盘和时间直接提交。

## 业务规则

### 甘特图可视化

- 主视图继续显示当前实验室的正式排程块。
- 当用户已经选择 `任务 + 实验` 后，甘特图额外叠加显示“当前任务已排程”的辅助占用块。
- 辅助占用块包含：
  - 已排程实验名称
  - 托盘编号摘要
  - 对应时间段
- 辅助占用块即使来自其他实验室，也需要在当前甘特区域显示，用于提醒该任务在该时段已有其他实验安排。
- 暂存间排程不参与该辅助展示；只统计正式实验室排程。

### 冲突判定

- 冲突检测只比较：
  - 当前待提交排程
  - 同一任务下其他正式实验的已存在排程
- 判定先看时间是否重叠：
  - 若时间不重叠，视为无冲突
  - 若时间重叠，再比较托盘交集
- 托盘交集为 `0`：
  - 不触发弹窗
- 托盘交集为“本次排程托盘的一部分”：
  - 判定为 `部分冲突`
- 托盘交集覆盖“本次排程全部托盘”：
  - 判定为 `完全冲突`
- 已存在排程与当前待提交排程属于同一实验时，不纳入本次任务内冲突提示。

### 冲突弹窗

- `部分冲突` 弹窗：
  - 标题：`部分冲突提示`
  - 色板：橙色系
  - 表达“存在风险，但允许继续排程”
- `完全冲突` 弹窗：
  - 标题：`完全冲突提示`
  - 色板：红色系
  - 表达“全部托盘都与其他实验重叠，但仍允许人工继续排程”
- 两类弹窗都显示：
  - 当前任务号
  - 当前实验名称
  - 冲突实验名称
  - 冲突实验室
  - 时间重叠区间
  - 冲突托盘
- 冲突托盘展示样式参考接驳区托盘标签：
  - 托盘编号为主
  - 附带实验标签
- 按钮统一为：
  - `确认排程`
  - `取消排程`

### 提交行为

- 无冲突：
  - 直接按现有逻辑提交
- 有冲突且用户点击 `取消排程`：
  - 不写入排程
  - 保留当前表单内容
- 有冲突且用户点击 `确认排程`：
  - 按原定任务、实验、托盘和时间提交
  - 不自动修改托盘集合
  - 不自动调整开始结束时间

## 数据与视图模型

### 排程读模型补充

排程页视图模型需要新增两类派生数据：

1. `taskScheduledOverlays`
   - 当前所选任务的其他正式实验排程占用块
   - 供甘特图辅助提示使用
2. `pendingConflict`
   - 当前待提交排程的冲突结果
   - 包含：
     - `level`: `partial` / `full`
     - `taskCode`
     - `experimentLabel`
     - `conflictSchedules`
     - `conflictTrayNos`
     - `overlapRange`

### 托盘来源

- 冲突判定必须基于任务托盘与实验托盘关系，而不是只基于任务号和实验号。
- 也就是说，排程模型需要能拿到：
  - 当前实验已勾选的托盘
  - 其他实验已排程时占用的托盘
- 如果某历史排程缺少托盘信息，需要按“无托盘明细”降级处理：
  - 仍可显示已排程辅助块
  - 但不触发托盘级别冲突弹窗

## 页面设计

### 表单区

- 现有排程表单结构保持不变。
- `确认排程` 仍是主按钮。
- 当存在冲突时，主按钮触发弹窗，而不是直接写入。

### 甘特图区

- 现有实验室排程块保留原交互和点击详情能力。
- 新增“当前任务已排程”辅助块样式：
  - 与正式排程块视觉区分
  - 使用边框、浅底或斜纹强调
  - 展示实验名称与托盘摘要
- 若当前表单已选任务但尚未选实验，则不显示辅助块。

### 冲突确认弹窗

- 使用与现有抽屉/模态一致的弹窗容器。
- 内容结构建议：
  - 顶部：冲突级别标题 + 风险说明
  - 中部：冲突实验条目列表
  - 底部：冲突托盘标签组
  - 操作区：`取消排程` / `确认排程`

## 测试范围

### 视图模型测试

1. 已选择任务和实验时，能计算出“当前任务已排程”辅助块。
2. 时间重叠且托盘部分相交时，返回 `部分冲突`。
3. 时间重叠且托盘完全相交时，返回 `完全冲突`。
4. 无时间重叠或无托盘交集时，不返回冲突确认数据。

### 页面运行时测试

1. 第二个实验排程时，甘特图能看到该任务已有排程辅助块。
2. `部分冲突` 时出现橙色确认弹窗。
3. `完全冲突` 时出现红色确认弹窗。
4. 点击 `取消排程` 不落库。
5. 点击 `确认排程` 仍按原逻辑落库。
6. 现有无冲突排程流程不回归。

## 成功标准

1. 多实验任务在排第二个实验时，排程员能直接看到该任务已有排程时间段。
2. 系统能区分 `部分冲突` 和 `完全冲突`。
3. 两类冲突都通过弹窗明确展示冲突托盘和关联实验。
4. 用户仍可人工确认强制排程，系统不擅自改动托盘或时间。
