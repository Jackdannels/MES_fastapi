# 接驳区系统扫码出库设计

## 背景

接驳区系统当前已经复用了中控中的“样品流程管理”面板，可完成任务选择、样品编号生成、托盘分装、确认入库与编码打印。

下一步需要在同一面板中增加一个轻量的“扫码出库”入口，用于对已生成标签的托盘执行出库操作。扫码结果是托盘编号，出库动作会将该托盘及所属样品推进到下一段流转状态。

## 目标

本轮实现以下能力：

1. 在接驳区系统的“样品流程管理”面板右下角新增扫码出库区
2. 承接扫码枪或手工输入的托盘编号
3. 同时展示“暂存间”卡片和试验类型对应的实验室卡片
4. 已排程命中的实验室卡片高亮并可选，未排程实验室卡片灰显不可选
5. 点击卡片后执行单托盘出库
6. 出库时同步更新托盘状态、样品状态、样品流转状态与历史

本轮明确不做：

- 不接真实扫码枪驱动，先用输入框承接扫码结果
- 不做批量多托盘出库
- 不做“已到达暂存间 / 已到达实验室”的自动推进
- 不把入口复制到中控样品页，只在接驳区系统显示

## 交互设计

### 位置

扫码出库区放在“样品流程管理”左侧主操作区的右下角，也就是托盘编号预览和按钮区附近的空白区域。

### 触发条件

只有当前任务已经完成入库确认后，扫码出库区才进入可操作状态。未确认入库时仍显示该区域，但输入框、卡片与出库按钮保持禁用态。

### 出库区内容

扫码出库区包含：

1. 托盘编号输入框
2. 当前识别结果说明
3. 目的地卡片区
4. 执行出库按钮

### 目的地卡片

目的地卡片统一采用实验室卡片风格。

- `暂存间` 卡片始终显示，固定使用独立颜色，可直接点击
- 实验室卡片只显示当前任务试验类型对应的实验室
- 如果任务在某实验室存在排程，该卡片高亮且可点击
- 如果该任务在对应实验室没有排程，该卡片灰显不可点击

实验室卡片内展示：

- 实验室名称
- 试验类型
- 任务编号
- 排程时间

### 出库状态写入

- 选择 `暂存间`：托盘和样品状态写为 `送至暂存间`
- 选择高亮实验室：托盘和样品状态写为 `送至实验室`
- 送至实验室时直接跳过暂存间步骤，不先写入暂存间状态

## 数据规则

### 实验室来源

实验室候选集来自现有 `getLabsForTestType(testType)` 映射。

### 排程命中规则

当前任务的正式实验室排程来自 `mes.schedules`：

- 只使用非暂存间设备的排程
- 设备名与试验类型匹配的实验室卡片视为候选卡片
- 其中与该任务现有排程设备命中的卡片视为“高亮可选”

### 托盘出库作用域

单次出库只处理一个托盘编号：

- 只更新该托盘的 `tray.status`
- 只更新绑定该托盘的样品 `status` / `flow_status` / `location`
- 对应样品追加“扫码出库”历史

## 实现边界

### 组件层

- `SampleProcessPanel.vue`
  - 增加右下角扫码出库区
  - 仅通过 `samplesProcess` 透传的数据和方法工作
  - 增加开关参数，只在接驳区系统中显示

### 组合函数层

- `useSamplesProcess.js`
  - 增加对 `mes.schedules` 的读取
  - 维护扫码输入值、当前目的地卡片列表、当前选中卡片
  - 执行单托盘出库并持久化样品快照

### 模型层

- `samplesProcessModel.js`
  - 构建扫码出库卡片视图
  - 处理单托盘出库后的样品和托盘状态更新

## 验证目标

1. 接驳区系统页面右下角出现扫码出库区
2. 输入有效托盘编号后，同时看到暂存间卡片和实验室卡片
3. 未排程实验室卡片灰显不可选
4. 已排程实验室卡片高亮可选并显示任务编号、试验类型、排程时间
5. 点击暂存间后，托盘和样品状态变为 `送至暂存间`
6. 点击高亮实验室后，托盘和样品状态变为 `送至实验室`
