# 任务总览与中控未排程口径统一设计

## 背景

当前前端存在三处口径不一致：

1. 任务/托盘总览会把任务级“已排程”兜底到所有实验，导致一个实验已排程时，同任务下其他未排程实验也显示为已排程。
2. 任务/托盘总览对任务入库字段兼容了 `transferStatus/transfer_status`，但中控总览与导航红点只识别 `transfer_status`，导致同一批数据在不同页面显示不一致。
3. 中控总览“未排程实验计时”需要持续展示“已到货但未排程”的实验明细，并在超过 24 小时后高亮；这个口径应与任务总览和导航红点保持一致。

## 目标

1. 单个实验的显示状态按实验自身真实排程状态计算，不再被任务级已排程状态污染。
2. 前端统一只使用 `transfer_status` 作为“是否已入库”的字段口径。
3. 中控总览、任务总览、导航红点对“已入库且未排程超时”的判定完全一致。

## 方案

### 1. 实验状态按实验维度推导

在 `frontend/src/modules/task-overview/model.js` 中，实验显示状态改为以下优先级：

1. 实验自身状态不是 `待排程` 时，直接显示实验自身状态。
2. 当前实验存在正式实验室排程时，显示排程态。
3. 当前实验不存在正式实验室排程时，如果实验自身仍是 `待排程`，继续显示 `待排程`。
4. 仅在没有实验记录时，才允许回退到任务级状态。

这样同一任务下可以同时出现 `已排程` 与 `待排程`。

### 2. 入库字段统一为 `transfer_status`

把任务总览中对 `transferStatus` 的兼容删除，统一读取 `transfer_status`。同时检查中控总览与导航红点逻辑，确保都只按 `transfer_status === "已入库"` 判定。

### 3. 中控未排程计时与导航提醒统一

在 `frontend/src/modules/dashboard/model.js` 与 `frontend/src/App.vue` 中复用相同的判定标准：

1. 任务 `transfer_status === "已入库"`。
2. 实验存在 `unscheduled_since`。
3. 该实验当前没有正式实验室排程。
4. `now - unscheduled_since > 24h` 时标记为超时高亮/导航红点。

## 测试

1. 任务总览模型测试：同一任务一个实验已排程、另一个实验未排程时，状态分别显示 `已排程` 与 `待排程`。
2. 中控总览模型测试：已入库且未排程实验会进入计时列表；存在正式排程的实验不会进入该列表。
3. App 运行时测试：当存在满足条件的超时未排程实验时，任务/托盘总览导航显示红点。
