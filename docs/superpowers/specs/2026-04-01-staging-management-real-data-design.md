# 暂存间真实数据与固定托盘面板设计

## 背景

当前暂存间页面 `frontend/src/modules/staging-management/page.vue` 仍依赖本地写死的 `DEFAULT_OVERVIEW_ROWS`。这带来三个问题：

1. 页面仍显示旧任务编号，而系统当前真实任务号已经统一为 `SYLU-YYYY-MM-NNN`
2. `今日待入库 / 今日待出库` 只是统计静态状态，不能反映真实扫码入库和扫码出库
3. 页面中部列表高度会随内容变化，扫码按钮位置不稳定，不适合连续扫码操作

本轮需要把暂存间页面切换到真实托盘数据，并让控制台区域固定高度、稳定分页。

## 目标

本轮实现以下行为：

1. 暂存间页面中的任务编号统一显示真实托盘所属任务的当前新编号
2. 顶部三块 KPI 同时改成“显示兼按钮”，点击后仅做列表筛选，不允许代入出入库流程
3. KPI 文案改为：
   - `暂存间中样品数量`
   - `今日已入库`
   - `今日已出库`
4. `今日已入库` 统计当天已经在暂存间完成扫码入库的托盘数
5. `今日已出库` 统计当天已经在暂存间完成扫码出库的托盘数
6. 中间托盘显示区固定为 5 行高度，无论筛选结果如何，扫码入库/出库按钮位置都不变
7. 中间区域每页最多显示 5 行托盘，超出后通过上下页切换
8. 点击扫码入库/出库后直接进入编辑模式，方便扫码枪或键盘连续输入

本轮明确不做：

- 不允许点击 KPI 或列表行直接触发出入库
- 不改变“只能扫码触发入库/出库”的业务边界
- 不重构暂存间为新路由或独立后端模块

## 数据设计

### 数据来源

暂存间页不再使用静态行数据，而是从真实存储快照推导：

- `mes.tasks`
- `mes.samples`
- 新增 `mes.staging_events`

`mes.staging_events` 用于记录暂存间自己的扫码事件，不复用样品当前状态做“今日”统计，以免后续状态覆盖历史事实。

### staging_events 结构

每条事件至少包含：

- `id`
- `tray_code`
- `task_code`
- `action`
  - `stock_in`
  - `stock_out`
- `time`
- `operator`

### 暂存间列表行推导

列表按托盘聚合，不按样品逐条显示。每一行至少展示：

- 任务编号
- 托盘编号
- 来源
- 样品类型
- 数量
- 当前位置
- 入库时间
- 状态

任务编号优先使用真实样品上的 `task_code`，从而直接显示最新 `SYLU` 编号。

### 状态推导

列表中的页面状态只保留三种：

- `待入库`
  - 托盘当前位于“送至暂存间 / 已到达暂存间”链路，但尚未出现暂存间 `stock_in`
- `已入库`
  - 已有暂存间 `stock_in`，且最后一次事件不是 `stock_out`
- `已出库`
  - 最后一次暂存间事件为 `stock_out`

## KPI 与筛选

### KPI 口径

- `暂存间中样品数量`
  - 统计当前未处于 `已出库` 的托盘内样品数量总和
- `今日已入库`
  - 统计今天发生 `stock_in` 的托盘数
- `今日已出库`
  - 统计今天发生 `stock_out` 的托盘数

### 点击行为

顶部三块卡片同时承担筛选功能：

- 点击 `暂存间中样品数量`
  - 展示当前仍在暂存链路中的托盘，即 `待入库 + 已入库`
- 点击 `今日已入库`
  - 展示今天完成扫码入库的托盘
- 点击 `今日已出库`
  - 展示今天完成扫码出库的托盘

点击只影响中间托盘显示区，不影响扫码流程，也不允许把某行自动带入扫码输入框。

## 页面布局

### 控制台结构

暂存间控制台拆成三段：

1. 顶部 KPI 按钮卡
2. 中间固定高度托盘显示区
3. 底部扫码入库 / 扫码出库按钮区

### 固定高度托盘显示区

中间区域采用固定 5 行高度：

- 即使当前只有 1 行，也保留 5 行占位高度
- 即使切换不同 KPI 或搜索条件，底部扫码按钮也不移动
- 超出 5 行时使用上一页 / 下一页切换

列表区仍显示托盘及任务信息，但不承载操作入口。

## 扫码交互

### 打开方式

点击 `扫码入库` 或 `扫码出库` 后，直接打开对应弹层并进入可编辑模式。

输入框需要在弹层打开后自动聚焦，便于：

- 扫码枪直接回填
- 键盘直接输入

### 入库

扫码入库成功后：

- 写入一条 `stock_in` 事件
- 若托盘此前处于 `待入库`，则页面状态变为 `已入库`
- 更新 `今日已入库`

### 出库

扫码出库成功后：

- 写入一条 `stock_out` 事件
- 页面状态变为 `已出库`
- 更新 `今日已出库`

## 测试范围

### 模型

需要覆盖：

1. 从真实 `tasks + samples + staging_events` 推导托盘行
2. 任务编号显示为真实新编号
3. `今日已入库 / 今日已出库` 按事件时间统计
4. KPI 点击筛选结果正确
5. 每页固定按 5 行分页

### 页面

需要覆盖：

1. 顶部三块卡片文案更新并可点击
2. 中间区域切换筛选时底部扫码按钮仍存在且位置结构不变
3. 扫码弹层打开后输入框直接可编辑并获得焦点
4. 每页最多显示 5 行，分页按钮能切换
5. 列表点击不会触发扫码流程
