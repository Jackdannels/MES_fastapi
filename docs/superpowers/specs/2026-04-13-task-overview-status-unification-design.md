# 任务总览排程实验计数与状态口径统一设计

## 背景

当前系统在运行态和完成态上存在多套含义相同但文案不一致的状态值：

- 运行态并存：`实验中`、`实验进行中`
- 完成态并存：`实验完成`、`实验已完成`、`实验已经完成`

这会带来三个问题：

- 前后端统计口径不稳定，同一业务状态在不同模块里被视为不同值。
- 任务/托盘总览顶部只有“已排程总任务数”，缺少实验维度的排程统计。
- 旧 JSON / MySQL 数据里仍保留历史值，即使新逻辑兼容读取，也会持续污染后续写入和展示。

用户确认的目标是：前后端统一口径，运行态唯一标准值为 `实验进行中`，完成态唯一标准值为 `实验已完成`，并同步修正旧数据；同时在任务/托盘总览顶部新增 `已排程总实验数` 卡片。

## 目标

- 全系统统一运行态标准值为 `实验进行中`
- 全系统统一完成态标准值为 `实验已完成`
- JSON 存储和 MySQL 历史数据中的旧值同步迁移为新值
- 在任务/托盘总览任务模式顶部新增 `已排程总实验数` 卡片
- 新卡片在有筛选时跟随当前筛选结果变化

## 方案对比

### 方案一：推荐，统一标准值并做存储层迁移

- 在存储层和业务模型层统一兼容旧值输入、输出新值
- 对 JSON 与 MySQL 历史数据做实际回写/回填
- 任务总览模型新增实验计数字段，顶部卡片从筛选后的任务行聚合

优点：

- 口径真正收敛，不是“显示统一、数据仍脏”
- 顶部卡片与任务卡片使用同一任务行模型，筛选联动稳定
- 后续新功能不再反复兼容多套历史状态

缺点：

- 改动面覆盖前后端多个模块与测试

### 方案二：只在前端展示层兼容旧值

- 前端把旧值映射成新文案，后端和存储不迁移

优点：

- 改动快

缺点：

- API、数据库、页面三层口径仍不一致
- 新卡片和别的统计点仍可能因为旧值漏算

### 方案三：只做新卡片，不统一状态口径

- 任务总览增加实验卡片，但继续兼容现有多套状态字符串

优点：

- 最小改动

缺点：

- 问题会继续蔓延，后续每个统计点都要重复兼容旧值

## 最终设计

### 标准状态

- 运行态唯一标准值：`实验进行中`
- 完成态唯一标准值：`实验已完成`

### 兼容输入

- 旧运行态 `实验中` 视为兼容输入，读入后归一为 `实验进行中`
- 旧完成态 `实验完成`、`实验已经完成` 视为兼容输入，读入后归一为 `实验已完成`

### 旧数据迁移

#### JSON 存储

- 在 `normalize_storage_payload` 路径里归一以下字段并回写文件：
  - `mes.tasks[].status`
  - `mes.experiments[].status`
  - `mes.schedules[].status`
  - `mes.samples[].status`
  - `mes.samples[].flow_status`
  - `mes.samples[].trays[].status`
  - `mes.samples[].history[].status`
  - 样品历史 `detail` 中形如 `任务 / 实验名 / 状态` 的实验状态片段

#### MySQL 存储

- 读取映射统一输出标准值
- 扩展 `_sync_progress_statuses()`，对 `biz_experiment`、`biz_task`、`biz_schedule` 的历史旧值做回填
- 任务与实验的派生状态输出统一改为标准值

### 任务/托盘总览新卡片

- 仅在 `viewMode === "task"` 时显示双卡片
- 位置：现有 `已排程总任务数` 卡片右侧，`任务总览/托盘总览` 切换按钮左侧
- 样式与现有卡片一致
- 标题：`已排程总实验数`
- 数值格式：`已排程实验数/总实验数`

### 新卡片统计口径

- 统计范围：当前筛选结果里的任务集合
- 若任务状态为 `厂家收回`，该任务下所有实验不计入分子和分母
- 分母 `总实验数`：上述任务集合下的全部实验数
- 分子 `已排程实验数`：状态属于以下任一值的实验数
  - `已排程`
  - `实验准备就绪`
  - `工装夹具安装`
  - `实验进行中`
  - `放置实验后暂存间`
  - `实验已完成`

### 任务总览任务行模型

- 每个任务行新增：
  - `eligibleExperimentCount`
  - `scheduledExperimentCount`
- 顶部卡片直接从 `filteredRows` 聚合，不重复扫原始快照

## 影响范围

- 存储层：
  - `app/core/storage_backend.py`
  - `app/core/mysql_storage_backend.py`
- 前端任务总览：
  - `frontend/src/modules/task-overview/model.js`
  - `frontend/src/modules/task-overview/useTaskOverview.js`
  - `frontend/src/modules/task-overview/TaskOverviewToolbar.vue`
- 前端状态统一相关模块：
  - `frontend/src/modules/tasks/model.js`
  - `frontend/src/modules/process/model.js`
  - `frontend/src/modules/process/useProcessLabs.js`
  - `frontend/src/modules/schedule/model.js`
  - `frontend/src/modules/laboratory/model.js`
  - 其他直接显示旧状态文案的页面/测试

## 测试策略

- 后端：
  - JSON 存储读写会把旧状态迁移并回写
  - MySQL 映射和派生状态统一输出标准值
- 前端任务总览：
  - 任务行正确计算实验分子/分母
  - 顶部新增卡片渲染正确
  - 筛选后卡片跟随 `filteredRows` 变化
  - `厂家收回` 任务被整体排除
- 前端状态统一：
  - 关键模块继续接受旧输入，但展示/输出统一为标准值
