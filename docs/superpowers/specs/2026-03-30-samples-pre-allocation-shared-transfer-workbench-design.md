# 样品预分装共享接驳工作台 Design

## 1. 背景

当前 `样品管理` 页面顶部使用 `SampleProcessPanel` 提供一套轻量的“样品流程管理”能力，能够按任务选择样品、分配托盘、确认入库、打印编码与重新入库。与此同时，`接驳区工作台` 已经存在一套更完整的“总任务清单 -> 任务工作区 -> 托盘分装/保存/打印/确认入库/重新入库”工作流，并且拥有成熟的运行时测试与共享工作区接口。

本次需求不是继续增强旧的 `SampleProcessPanel`，而是把 `样品管理` 顶部区域改造成“预接驳版接驳区工作台”，用于中控系统提前完成样品预分装。中控与接驳区必须使用完全同一份任务工作区数据，接驳区打开任务时需要直接看到中控保存的托盘分配结果。

## 2. 目标

- 将 `样品管理` 顶部的“样品流程管理”替换为“样品预分装”工作台。
- 界面入口改成与接驳区工作台一致的 `总任务清单 -> 任务样品分配管理`。
- 中控预分装与接驳区共用同一份工作区数据。
- 中控允许 `保存托盘`、`打印条形码`、`重新分配`，但不允许 `确认入库`。
- 接驳区继续承担最终的 `确认入库 / 重新入库` 职责。
- `样品流转与状态`、`暂存间派发` 保持不动。
- 删除 `样品全生命周期追踪` 区块。

## 3. 非目标

- 不修改 `样品流转与状态` 的表格结构、分页与筛选逻辑。
- 不修改 `暂存间派发` 的交互与数据模型。
- 不重写接驳区后端接口协议。
- 不新增“预分装草稿”和“正式草稿”两套独立存储。

## 4. 现状分析

### 4.1 样品模块现状

- `frontend/src/modules/samples/page.vue` 顶部挂载 `SampleProcessPanel`。
- `frontend/src/modules/samples/useSamplesProcess.js` 和 `samplesProcessModel.js` 维护一套独立的托盘草稿模型。
- 这套模型把“确认入库”直接写回任务与样品快照，不具备“总任务清单 -> 工作区”模式，也没有与接驳区共享工作区数据。

### 4.2 接驳区模块现状

- `frontend/src/modules/handover-system/page.vue` 已实现完整的总览、详情、托盘编辑、保存、打印、确认入库、重新入库。
- 页面通过 `/api/transfer-area/bootstrap`、`/workspace`、`/allocate`、`/print-barcodes`、`/confirm-storage`、`/reload` 等接口工作。
- 运行时测试已经覆盖总任务清单、入库状态筛选、打印、确认、重新入库等主要链路。

### 4.3 关键差异

接驳区与中控的差异不是“数据结构不同”，而是“可执行动作不同”。两边都编辑同一份工作区，但：

- 中控是“预接驳/预分装”
- 接驳区是“正式接驳/正式入库”

因此最优方案是抽出共享工作台，再通过模式配置约束按钮、标题、说明文案和只读策略。

## 5. 设计方案

### 5.1 总体方案

抽出“共享接驳工作台”，由两个模式驱动：

- `handover` 模式：现有接驳区工作台
- `pre-allocation` 模式：样品管理里的“样品预分装”

两种模式共享：

- 总任务清单
- 任务工作区加载
- 托盘布局、编辑、保存
- 条码生成与打印
- 工作区状态同步

两种模式差异由配置决定：

- 标题、副标题、按钮文案
- 是否显示 `确认入库`
- `重新入库` 是否显示为 `重新分配`
- 已入库任务是否只读

### 5.2 页面结构

`样品管理` 页面调整为：

1. 顶部：`样品预分装` 共享工作台（`pre-allocation` 模式）
2. 中部：保留 `样品流转与状态`
3. 下部：保留 `暂存间派发`
4. 删除：`样品全生命周期追踪`

### 5.3 样品预分装总任务清单

总任务清单结构沿用接驳区工作台，但筛选入口改成参考 `试验过程管控` 的统计卡片。

卡片设计：

- `未入库`
- `已入库`
- `全部`

规则：

- 默认选中 `未入库`
- 卡片既显示数量，也可点击切换筛选
- `已入库` 任务允许进入详情查看与打印
- `未入库` 任务允许进入详情编辑托盘

### 5.4 任务详情页

详情页基本复用接驳区现有布局：

- 任务头部信息
- 实验 pill 切换
- 托盘栏位编辑区
- 统一上限
- 新增托盘
- 托盘预览

中控 `pre-allocation` 模式按钮区：

- `打印条形码`
- `保存托盘`
- `重新分配`

中控不显示：

- `确认入库`

按钮口径：

- `保存托盘`：直接保存到共享工作区
- `打印条形码`：与接驳区使用同一套条码生成与预览
- `重新分配`：把当前任务恢复为可编辑未确认状态，清除已打印/已保存后的锁定效果，重新回到托盘可编辑草稿

### 5.5 工作区与同步口径

中控与接驳区必须使用完全同一份工作区数据。

这意味着：

- 中控点击 `保存托盘`，直接调用与接驳区相同的分配保存逻辑
- 接驳区打开同一任务时，直接看到相同的托盘数量、托盘编号、样品摆放、实验托盘选择结果
- 中控点击 `重新分配` 后，接驳区再次打开同一任务时，也看到重置后的工作区

不引入：

- 预分装草稿表
- 预分装专属缓存
- 中控与接驳区双写同步逻辑

### 5.6 已入库任务规则

- 在中控总任务清单中可见
- 允许打开详情
- 详情页进入只读态
- 允许 `打印条形码`
- 不允许编辑托盘、保存托盘、重新分配
- 不显示 `确认入库`

### 5.7 删除旧样品流程管理

旧的 `SampleProcessPanel` / `useSamplesProcess` / `samplesProcessModel` 不再承担页面入口职责。

处理策略：

- 页面上移除 `SampleProcessPanel`
- 如果共享工作台完全取代其功能，可逐步删除不再被引用的 `useSamplesProcess` 和 `samplesProcessModel`
- 如第一阶段仍需保留文件供迁移过渡，必须确保页面不再使用旧入口与旧按钮

## 6. 文件边界建议

### 6.1 共享工作台层

建议从 `frontend/src/modules/handover-system/` 拆出：

- 共享页面壳层组件
- 共享运行时状态组合逻辑
- 共享模式配置

### 6.2 接驳区页面

`frontend/src/modules/handover-system/page.vue`

- 收缩为挂载共享工作台的 `handover` 模式入口

### 6.3 样品页面

`frontend/src/modules/samples/SamplesManagementPanel.vue`

- 顶部挂载共享工作台的 `pre-allocation` 模式
- 删除追踪模块引用

`frontend/src/modules/samples/page.vue`

- 删除 `useSampleTrace` 相关注入
- 删除 `sampleTrace` 响应式桥接

## 7. 错误处理

- 工作区加载失败：沿用接驳区的空态/错误态提示与重载按钮
- 保存托盘失败：保留错误文案，不覆盖本地已编辑状态
- 中控误触入库：界面层根本不暴露 `确认入库`
- 已入库任务编辑：通过统一只读锁阻止托盘编辑、删除、新增、重新分配

## 8. 测试策略

### 8.1 共享工作台

- 总任务清单默认选中 `未入库`
- 点击统计卡片可切换到 `已入库` / `全部`
- 打开任务后能加载共享工作区

### 8.2 中控预分装模式

- 显示 `样品预分装`
- 不显示 `确认入库`
- `重新入库` 文案改为 `重新分配`
- 能保存托盘
- 能打印条形码
- 已入库任务详情只读但可打印

### 8.3 接驳区模式

- 现有 `确认入库 / 重新入库` 行为保持不变
- 既有运行时测试继续通过

### 8.4 样品页面结构

- 顶部旧 `样品流程管理` 不再出现
- `样品全生命周期追踪` 不再出现
- `样品流转与状态` 和 `暂存间派发` 仍然存在

## 9. 风险与约束

- 如果直接复制接驳区页面而不做共享抽取，后续两套页面会快速漂移
- 如果继续扩展 `useSamplesProcess`，会形成第二套托盘模型，与共享工作区目标冲突
- `重新分配` 与接驳区的 `重新入库` 含义接近但职责不同，需通过模式配置明确按钮文案和提示文本，避免误导用户

## 10. 结论

本次改造应以“共享工作台 + 模式化权限”为核心。样品管理中的“样品预分装”不是一套新业务，而是接驳区工作台的中控预处理入口。只要两边共享同一份工作区数据，并将差异压缩到模式配置、筛选卡片和按钮权限，中控预分装与接驳区正式入库就能稳定协作，同时避免维护两套近似页面。
