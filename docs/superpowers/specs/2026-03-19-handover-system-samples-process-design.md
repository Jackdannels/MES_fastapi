# 接驳区系统样品流程管理首段接入设计

## 背景

当前前端已经存在：

- `中控管理系统`
- `可视化管理`
- `暂存间管理`

登录入口已经支持按系统切换，但还没有 `接驳区系统`。用户当前需要先落一个最小切口：在登录页新增独立模块入口，并把中控管理系统中的 `样品管理 -> 样品流程管理` 整块能力复制到接驳区系统中，作为后续接驳区系统继续扩展的起点。

这里的“复制”优先指页面能力复制，而不是复制一套独立数据。接驳区系统必须与中控管理系统联动，因此首版仍应复用现有样品流程管理逻辑和存储。

## 目标

本轮只实现以下内容：

1. 登录页新增 `接驳区系统` 入口
2. 模块注册中心新增一个独立模块
3. 登录后可进入接驳区系统独立页面
4. 接驳区系统页面首版只展示 `样品流程管理` 面板
5. 页面继续复用当前 `useSamplesProcess` 相关逻辑，与中控管理系统共用同一套任务/样品/托盘数据

本轮明确不做：

- 不新建独立后端表
- 不复制 `样品登记 / 样品流转 / 暂存间 / 托盘管理 / 样品追溯`
- 不新增接驳区专属状态机
- 不调整现有中控管理系统导航结构

## 方案

### 入口方案

在登录页系统选择下拉中新增 `接驳区系统`，作为独立模块入口，而不是把接驳区能力塞回现有 `samples` 模块内部。

这样做的原因是：

- 用户明确要求独立模块入口
- 后续接驳区系统大概率会继续扩展，不应长期依附在中控页内
- 复用页面片段与独立模块入口不冲突，入口和实现层应分离

### 页面方案

接驳区系统首版页面不重做业务逻辑，只复用中控中 `样品流程管理` 这一个面板。

建议把当前 `SamplesManagementPanel.vue` 里的“样品流程管理”部分抽成一个独立子组件，例如：

- `SampleProcessPanel.vue`

然后由两个页面消费：

- 中控中的 `SamplesManagementPanel.vue`
- 新增的接驳区系统页面

这样做可以避免复制大段模板后产生双份维护。

### 数据联动

接驳区系统首版继续直接使用现有：

- `useSamplesProcess`
- 当前任务选项
- 当前样品、托盘和任务写回链路

这意味着：

- 接驳区系统里选择任务、确认入库、重新入库、托盘分装
- 会继续作用在与中控相同的样品/任务数据上
- 中控和接驳区天然联动，不需要额外同步层

### 路由与模块

新增一个独立模块，例如：

- `frontend/src/modules/handover-system`

模块职责：

- 提供独立路由
- 定义模块标题和导航归属
- 承载首版接驳区页面

页面只显示：

- 页面标题
- `样品流程管理` 面板

不引入中控中其它页面段落，避免首版范围扩散。

## 影响范围

### 登录与模块注册

- `frontend/src/modules/login/page.vue`
  - 登录页系统下拉新增 `接驳区系统`
- `frontend/src/auth.js`
  - 扩展登录模块 key 与首页路由映射
- `frontend/src/modules/index.js`
  - 注册新模块

### 新模块

- 新建 `frontend/src/modules/handover-system/index.js`
- 新建 `frontend/src/modules/handover-system/page.vue`
- 新建 `frontend/src/modules/handover-system/styles.css`（如需要）

### 复用样品流程管理面板

- 从 `frontend/src/modules/samples/SamplesManagementPanel.vue` 中抽出 `样品流程管理` 子组件
- 新子组件继续依赖现有 `samplesProcess` 对象，不引入新状态源

### 测试

- 登录页运行时测试：验证系统下拉出现 `接驳区系统`
- 模块结构测试：验证新模块注册
- 新页面运行时测试：验证接驳区系统页面能渲染样品流程管理面板
- 复用回归：验证中控里的原样品流程管理仍可正常工作

## 验证目标

1. 登录页可选 `接驳区系统`
2. 登录后能进入独立接驳区页面
3. 页面能看到与中控一致的 `样品流程管理` 面板
4. 面板交互继续使用现有任务/样品数据
5. 中控中的样品流程管理原功能不回退
