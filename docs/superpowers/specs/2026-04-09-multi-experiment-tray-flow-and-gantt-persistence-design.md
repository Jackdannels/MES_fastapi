# 多实验托盘流程图与甘特保留设计

## 背景

当前系统的托盘流程图建立在单一固定流程之上，适合单实验托盘，但无法准确表达“同一个托盘依次完成 A/B/C 多个实验”的生命周期。现有展示存在两个问题：

1. 已完成实验的中间步骤仍占据大量流程节点，导致三实验及以上任务的流程图难以阅读。
2. 甘特图会基于原计划时间或完成过滤规则过早隐藏排程，即使实验尚未真正开始，或者刚开始后仍应继续显示排程。

本次设计将统一修改共享托盘流程图模型，并修正甘特图隐藏规则。修改范围覆盖中控管理、接驳区、样品/托盘管理、实验室操作台、试验过程管控等所有使用共享托盘流程图的界面。

## 目标

1. 支持一个托盘按顺序完成多个实验，并在流程图中显示 `A实验已完成 / B实验已完成 / C实验已完成` 这类实验里程碑。
2. 当前未完成实验保留完整前序步骤显示：到实验室、比对确认、工装夹具安装、实验准备就绪、实验进行中。
3. 已完成实验压缩展示，只保留对应实验的完成节点，不再展开已完成实验的待执行、比对、安装、准备等中间节点。
4. 当前实验完成后，不预判下一去向；根据后续真实动作，自动判别是先去暂存间还是先进入下一个实验室。
5. 日志与历史记录不删减，仍完整记录托盘全生命周期；压缩规则只作用于流程图显示。
6. 甘特图仅在“实验已正式开始且已真实完成”后才允许隐藏排程。未正式开始时，即使超过原计划时间也继续显示。

## 非目标

1. 不重写现有样品/托盘底层状态模型。
2. 不删除任何历史流转日志。
3. 不在本次设计中新增后端独立流程表；继续以现有样品、托盘、排程和实验关系为主数据源。
4. 不改变“开始实验必须由试验过程管控显式点击触发”的既有规则。

## 当前系统约束

### 托盘流程图

共享托盘流程图当前由 `frontend/src/modules/samples/samplesFlowModel.js` 中的 `buildTrayFlowView(...)` 构建，使用单一固定步骤：

- 样品运输中
- 到货
- 送至暂存间
- 已到达暂存间
- 送至实验室
- 已到达实验室
- 工装夹具安装
- 实验准备就绪
- 实验进行中
- 实验已完成
- 放置实验后暂存间
- 厂家收回

该模型无法区分多个实验的顺序，也无法在流程图中表达“某一实验已完成而下一实验尚未开始”的阶段。

### 甘特图

排程看板当前在 `frontend/src/modules/schedule/model.js` 中按排程时间和完成过滤构建甘特段。已有一条测试 `hides completed experiments from the gantt once their end time has passed`，说明当前模型默认会隐藏“已完成并过时”的实验。这会与“未正式开始不应消失”的新口径冲突。

## 设计方案

### 1. 托盘流程图升级为多实验压缩视图

共享托盘流程图从“固定 12 步”升级为“主干流转 + 实验里程碑 + 当前实验展开”的组合模型。

#### 1.1 主显示规则

对一个按 `A -> B -> C` 顺序执行的托盘，流程图展示遵循以下规则：

- 保留全局起点 `到货`
- 已完成的历史实验仅保留完成里程碑：
  - `A实验已完成`
  - `B实验已完成`
- 当前未完成实验保留完整展开流程：
  - `送至实验室`
  - `已到达实验室`
  - `比对确认`
  - `工装夹具安装`
  - `实验准备就绪`
  - `实验进行中`
  - `当前实验待完成 / 当前实验已完成`
- 当前实验完成后，不预先生成下一目标节点，直到系统观察到下一个真实动作

#### 1.2 三实验示例

当 A 已完成、正在准备 B 时：

- 到货
- A实验已完成
- 送至暂存间
- 已到达暂存间
- 送至实验室
- 已到达实验室
- 比对确认
- 工装夹具安装
- 实验准备就绪
- B实验待执行

当 A、B 已完成，当前正在做 C 时：

- 到货
- A实验已完成
- B实验已完成
- 送至暂存间（若真实发生）
- 已到达暂存间（若真实发生）
- 送至实验室
- 已到达实验室
- 比对确认
- 工装夹具安装
- 实验准备就绪
- 实验进行中
- C实验待完成

当 A、B、C 全部完成时，保留最后一个实验的前序路径：

- 到货
- A实验已完成
- B实验已完成
- 送至暂存间 / 已到达暂存间 / 送至实验室 / 已到达实验室（仅保留真实发生的最后一段转运）
- 比对确认
- 工装夹具安装
- 实验准备就绪
- 实验进行中
- C实验已完成

### 2. 自动判别实验完成后的下一去向

系统不在“实验完成”这一刻直接写死下一目标，而是根据后续真实动作自动判别。

#### 2.1 判别优先级

当前实验完成后：

1. 若首先发生 `暂存间入库 / 已到达暂存间`，则流程图显示：
   - `送至暂存间`
   - `已到达暂存间`
2. 若未先进入暂存间，而是首先在下一个实验室发生：
   - 扫码比对成功
   - 或托盘/样品状态进入 `已到达实验室`
   则流程图显示：
   - `送至实验室`
   - `已到达实验室`
3. 若两者都未发生，则流程图停留在：
   - `X实验已完成`

#### 2.2 事实优先

流程图只显示已发生的事实，不预判托盘将来去向。日志和历史记录仍完整保留，可供追溯。

### 3. 全系统统一影响范围

本次不做页面特判，而是修改共享流程模型，统一影响：

- 中控管理中的托盘流程图
- 样品/托盘管理中的统一托盘流程图
- 试验过程管控中的当前托盘流程图
- 各实验室操作台中的托盘流程图
- 其他直接调用共享托盘流程图构建器的界面

### 4. 甘特图保留规则修正

甘特图的排程可见性改为依赖“是否正式开始实验”和“是否真实完成”，而不是单独依赖原计划时间。

#### 4.1 新规则

- 未正式开始实验：
  - 即使当前时间已经超过原 `end_at`
  - 排程仍继续显示，不自动消失
- 已正式开始实验：
  - 以试验过程管控点击 `开始实验` 时重算后的真实 `start_at/end_at` 为准
  - 运行中继续显示
- 已完成实验：
  - 只有在实验真实完成，并达到/超过真实结束时间后，排程才允许隐藏

#### 4.2 关键判定

“正式开始实验”只由试验过程管控点击 `开始实验` 触发，实验室操作台的“确认实验准备就绪”不等同于开始实验。

## 数据来源与判定依据

### 实验顺序

实验顺序继续由任务下的实验关系和实验编码顺序决定，来源于：

- `mes.experiments`
- `mes.schedules`
- `mes.experiment_trays`

### 托盘归属与状态

托盘当前状态和实验关联继续从样品/托盘记录中推导，来源于：

- `mes.samples[].trays`
- `mes.experiment_trays`
- `mes.schedules`

若同一托盘绑定多个实验，流程图构建器需要结合当前实验顺序和真实事件，区分“历史已完成实验”和“当前目标实验”。

## 测试策略

### 托盘流程图

新增或更新测试覆盖：

1. 三实验托盘在不同阶段的流程图显示
2. 已完成实验压缩为 `X实验已完成`
3. 当前未完成实验保留完整展开流程
4. 完成实验后，根据真实动作自动显示：
   - `送至暂存间 / 已到达暂存间`
   - 或 `送至实验室 / 已到达实验室`
5. 全部实验完成后，仅保留最后一个实验的前序路径和完成节点
6. 多实验共享托盘编号时，流程图仍能保持正确阶段显示

### 甘特图

新增或更新测试覆盖：

1. 未正式开始实验时，超过原计划结束时间仍显示排程
2. 正式开始后，以重算后的时间显示排程
3. 正式完成后，达到真实结束条件才隐藏
4. 开始实验不应导致整张甘特图消失

## 风险

1. 共享流程图模型变更会影响多个页面，测试覆盖必须足够，否则容易出现某一页面口径漂移。
2. 多实验共享托盘时，需要明确“当前实验”的判定来源，避免不同页面对同一托盘显示不同实验阶段。
3. 甘特图隐藏条件如果仍存在旧时间过滤分支，可能继续出现“开始实验后整图消失”的问题，需要以失败测试锁定。

## 推荐实施顺序

1. 先为共享托盘流程图模型补三实验压缩显示失败测试
2. 实现新的多实验压缩流程图构建逻辑
3. 接入中控、托盘管理、过程管控、实验室操作台
4. 为甘特图补“未开始不隐藏 / 已开始按真实结束隐藏”的失败测试
5. 修正甘特图过滤逻辑
