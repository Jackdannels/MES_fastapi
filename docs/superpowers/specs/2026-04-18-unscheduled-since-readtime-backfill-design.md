# 读时回填未排程计时设计

## 背景

旧数据中部分实验已经满足“任务已入库、实验未正式排程”的条件，但 `mes.experiments[].unscheduled_since` 为空。中控总览和导航红点依赖这个字段，因此这些旧数据不会显示未排程计时，也不会触发红点。

## 目标

在读取存储快照时自动识别旧数据缺口，并把缺失的 `unscheduled_since` 回填到数据库，使后续所有页面和读取链路都拿到修正后的真实值。

## 方案

### 回填位置

在 `app/core/mysql_storage_backend.py` 的 MySQL 存储读路径中完成：

1. `read_all()`
2. `read("mes.experiments")`

两条路径在返回快照前都执行同一套回填逻辑。

### 回填条件

仅当以下条件同时成立时才回填：

1. 任务 `transfer_status = 已入库`
2. 实验没有正式排程
3. 实验 `unscheduled_since` 为空
4. 实验状态未开始、未完成、未收回

### 时间来源

优先使用该实验关联样品中的最早入库时间：

1. 优先读取样品历史中的 `任务已确认入库` 事件时间
2. 没有历史时退化为样品当前 `status/flow_status = 已入库` 的 `updated_at`
3. 多个样品取最早时间

### 样品关联规则

关联优先级如下：

1. `mes.experiment_samples`
2. `mes.experiment_trays + mes.samples[].trays`
3. 如果以上都缺失，则退化为同任务全部样品

### 落库方式

读时发现缺口后，立即只更新受影响实验的 `unscheduled_since`，然后返回修正后的结果；不重写整张实验表。

## 测试

1. 存储层测试：实验映射读写保留 `unscheduled_since`
2. 存储层测试：读时回填会为缺失字段的旧实验补写样品最早入库时间
3. 存储层测试：有正式排程或已开始/已完成实验不会被回填
