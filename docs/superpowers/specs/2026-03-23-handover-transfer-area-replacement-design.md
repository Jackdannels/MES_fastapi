# 接驳区工作台整套替换设计

## 背景

当前系统中的接驳区主界面位于 `frontend/src/modules/handover-system/`，现状是复用中控样品流程管理面板。用户提供的压缩包则是一套更完整的接驳区工作台，包含：

- 任务总览页
- 单任务托盘分装与入库详情页
- 条码预览与确认打印弹窗
- 专用后端接口定义 `transfer_area.py`

要满足“直接替换界面”的要求，不能只换前端样式。压缩包页面已经围绕 `/api/transfer-area/*` 的专用数据流设计，如果只复制界面文件，页面将无法工作。

## 目标

本轮实现以下能力：

1. 保留现有登录入口、模块 key 与 `/handover-system` 路由
2. 用压缩包中的接驳区工作台替换现有接驳区主界面
3. 新增 `/api/transfer-area/*` 专用接口，作为新页面唯一数据源
4. 后端继续复用现有 `mes.tasks`、`mes.samples`、`mes.schedules` 存储，不额外引入新存储表
5. 保持与系统其他页面的数据联动，避免形成独立的接驳区假数据

本轮明确不做：

- 不改登录流程和模块入口结构
- 不新增数据库表或新的持久化后端
- 不把压缩包页面拆回旧的 `useSamplesProcess` 前端逻辑

## 方案选择

已确认采用“整套模块接入”方案：

- 保留现有 `handover-system` 模块入口与路由
- 直接替换该模块前端文件为压缩包页面
- 同时接入压缩包依赖的后端 `transfer-area` API
- API 内部适配现有存储快照结构，而不是要求前端继续拼接旧逻辑

没有采用“纯前端替换”的原因是：压缩包页面不是静态换皮，而是完整工作台，包含总览、详情、托盘、条码、确认打印与重新载入等新交互。若继续绑定旧前端逻辑，实际改造成本更高，也更容易在行为上偏离成品界面。

## 前端设计

### 模块入口

- 继续使用 `frontend/src/modules/handover-system/index.js`
- 路由保持 `/handover-system`
- 模块标题仍显示“接驳区系统”

### 页面结构

接驳区模块改为双视图页面：

1. `overview`
   - 展示任务总览列表
   - 提供任务搜索、类型筛选、状态筛选、分页
   - 统计未入库任务数与已入库任务数
2. `detail`
   - 展示单任务基本信息
   - 展示托盘栏位、统一上限、托盘预览
   - 支持样品交换、移动、托盘新增与删除
   - 支持保存托盘、打印条码、确认入库、重新载入

### 前端数据边界

新页面不再直接依赖 `useSamplesProcess`。压缩包页面中所有任务视图、托盘视图和打印弹窗数据均来自 `/api/transfer-area/*`。前端只负责：

- 发起接口请求
- 维护当前页面视图状态
- 显示接口返回的任务、托盘和条码数据

这样可以把接驳区业务规则集中到后端，避免前端同时维护一份旧样品模型和一份新工作台模型。

## 后端设计

### 新增路由

新增 `app/api/routes/transfer_area.py`，统一提供以下接口：

- `GET /api/transfer-area/bootstrap`
- `GET /api/transfer-area/tasks/{task_id}/workspace`
- `POST /api/transfer-area/tasks/{task_id}/allocate`
- `POST /api/transfer-area/tasks/{task_id}/print-barcodes`
- `POST /api/transfer-area/tasks/{task_id}/confirm-storage`
- `POST /api/transfer-area/tasks/{task_id}/reload`

并在 `app/modules/registry.py` 中将该路由挂入 `handover-system` 模块。

### 数据来源

接口内部继续通过现有存储后端读取和回写：

- `mes.tasks`
- `mes.samples`
- `mes.schedules`

必要时使用现有 `get_storage_backend()` 直接读写快照，不新建额外的仓储层。

### 计算规则

#### bootstrap

返回接驳区总览页所需数据：

- 可进入接驳区处理的任务清单
- 已入库 / 未入库统计
- 任务编号、试验类型、样品编号、流程状态等摘要

接驳区总览不展示已经进入实验执行、实验完成或厂家收回的任务。判定规则优先复用现有样品与托盘状态映射，必要时从 `samplesProcessModel.js` 中提取纯规则函数到可复用位置。

#### workspace

返回单任务详情页所需工作区：

- 当前任务摘要
- 已分配托盘列表
- 可用空托盘库存
- 当前托盘上限

如果任务已入库，工作区应返回锁定态托盘与样品状态；如果未入库，则返回可编辑的托盘分装态。

#### allocate

保存当前托盘分配：

- 校验样品是否全部属于当前任务
- 校验是否有重复分配或遗漏分配
- 将托盘结果回写到样品 `trays`
- 更新任务托盘汇总信息

#### print-barcodes

基于当前已分装托盘生成条码预览数据：

- 仅对已装载样品的托盘生成条码
- 返回条码编号、内容和托盘映射
- 将条码信息回写到工作区对应托盘

页面中的条码 SVG 仍由前端本地渲染；后端只负责返回结构化条码数据。

#### confirm-storage

确认入库后：

- 将任务切换为“已入库”视图状态
- 将托盘状态与样品状态更新为已入库
- 写入样品历史，保留接驳区入库痕迹
- 让该任务从未入库统计切换到已入库统计

#### reload

重新载入用于撤销已确认入库后的接驳区锁定态：

- 将当前任务恢复为未入库工作态
- 清空打印确认结果
- 恢复托盘为待重新分装 / 待重新打印状态
- 让该任务重新回到未入库列表

## 状态与兼容性设计

新接口不会创建一套新的接驳区状态机，而是把页面显示状态映射到现有任务、样品、托盘信息上。

兼容原则：

- 已在实验执行中的任务不出现在可操作总览中
- 已实验完成、厂家收回的任务不出现在可操作总览中
- 已入库任务可以在总览中切换查看，但详情页默认是锁定态
- 接驳区入库、托盘、条码相关历史继续写入现有样品数据，保持中控和接驳区联动

## 测试设计

### 前端

替换 `frontend/src/modules/handover-system/` 下的运行时测试，覆盖：

- 总览页渲染
- 任务筛选和分页
- 详情页渲染
- 样品点击交换与移动托盘
- 打印条码后出现确认打印弹窗
- 确认入库后状态切换
- 重新载入后任务回到未入库列表

### 后端

新增 `tests/api/test_transfer_area.py`，覆盖：

- `bootstrap` 返回可操作任务与统计数据
- `workspace` 返回单任务托盘工作区
- `allocate` 保存托盘分配
- `print-barcodes` 返回条码预览并更新工作区
- `confirm-storage` 更新任务和样品状态
- `reload` 恢复任务为未入库工作态

### 回归

额外确认：

- `handover-system` SPA 路由仍可访问
- 前端构建或测试仍能通过
- 现有 `samples` 相关页面不因接驳区替换而被破坏

## 验收标准

1. 登录后进入 `/handover-system` 时，显示压缩包中的接驳区工作台，而不是旧的样品流程管理页
2. 总览页可看到待处理任务、筛选和分页
3. 点击任务后可进入托盘分装与入库详情页
4. 保存托盘、打印条码、确认入库、重新载入都能通过专用接口工作
5. 操作结果会回写现有存储快照，其他页面能看到同一批任务和样品状态变化
