# 总任务清单筛选联动设计

## 背景

总任务清单顶部工具栏包含搜索框、实验类型筛选和状态筛选。页面上控件位置已经符合使用习惯，但状态下拉选项来自全量任务，选择实验类型后状态选项不会随实验类型范围收窄。

用户确认的目标是：控件位置保持不变，先按实验类型限定任务范围，再在这个范围内统一进行搜索和状态选择。

## 目标

- 工具栏顺序保持为：搜索框、实验类型、状态。
- 选择实验类型后，状态下拉只显示该实验类型范围内实际存在的任务状态。
- 搜索框继续可用，但搜索范围应是实验类型和状态筛选后的任务集合。
- 状态筛选继续可用，并与搜索共同作用在当前实验类型范围内。
- 当实验类型变化导致当前状态选项不再存在时，自动清空状态筛选，避免页面显示空结果。

## 方案

在 `frontend/src/modules/tasks/useTasksPage.js` 中把筛选拆成分层计算：

- `typeFilteredRows`：只应用实验类型筛选。
- `statusOptions`：从 `typeFilteredRows` 构建，所以状态选项跟随实验类型变化。
- `filteredRows`：在 `typeFilteredRows` 上继续应用状态筛选。
- `useTableControls` 继续接收 `filteredRows`，因此搜索、排序和分页都运行在已筛选后的任务集合上。

页面组件 `frontend/src/modules/tasks/page.vue` 不改变控件顺序和布局，只消费更新后的 `statusOptions`。

## 测试策略

- 运行时测试覆盖：选择某个实验类型后，状态下拉只保留该实验类型下的状态。
- 运行时测试覆盖：在实验类型范围内选择状态后，搜索继续只搜索该范围内的任务。
- 运行时测试覆盖：实验类型变化时，如果原状态不再可选，状态筛选自动清空。
