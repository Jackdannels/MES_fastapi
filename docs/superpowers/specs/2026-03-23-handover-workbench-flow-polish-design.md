# 接驳区工作台流程修正设计

## 背景

当前接驳区工作台已经具备任务总览、托盘分装、条码预览和入库确认能力，但实际使用中还存在几个关键问题：

1. 总览页分页区会随着任务行高度波动
2. 条码“确认打印”仅改状态，不会触发实际浏览器打印
3. 统一上限调整后不会自动按顺序重排托盘
4. 保存托盘后仍被“必须已打印条码”限制，无法直接确认入库
5. 非空托盘不能删除，不符合自动重排的工作预期

本轮目标是修正这些交互与业务规则，不重写接驳区模块整体架构。

## 目标

本轮实现以下能力：

1. 总览页分页区位置固定，不因样品标签多少产生上下漂移
2. 点击条码弹窗中的“确认打印”后触发浏览器实际打印
3. 默认统一上限为 `4`
4. 详情页首次进入、调整统一上限、删除托盘时，都自动按样品顺序重排到最小托盘数
5. 非空托盘允许删除，删除后自动重排剩余样品
6. 保存托盘后即可确认入库，不再要求先打印条码
7. 保存成功后，“保存托盘”按钮进入禁用态，直到用户再次修改托盘布局
8. 新增托盘沿用当前任务托盘编号前缀，仅末尾序号递增
9. 未保存托盘前，打印按钮保持禁用态
10. 删除不合理时给出明确提示，而不是静默失败
11. 已保存托盘再次重新分配后，旧接驳历史与旧托盘编号不再保留
12. 详情页底部动作按钮文案统一为“重新入库”

本轮明确不做：

- 不接入操作系统级打印机驱动
- 不新增独立打印服务
- 不改接驳区路由和整体视觉框架

## 交互设计

### 总览页分页区

总览卡片改成固定三段结构：

- 标题与筛选区
- 任务表格主体
- 底部分页区

表格主体承担内容伸缩，分页区始终固定在卡片底部。样品标签多时，表格区内部扩展，但分页按钮位置保持稳定。

### 统一上限与托盘自动重排

进入详情页后，系统读取当前任务样品并按以下规则自动生成初始托盘：

- 默认统一上限为 `4`
- 使用满足容量的最小托盘数
- 按样品编号顺序依次放入托盘

当用户调整统一上限时：

- 当前托盘布局立即按新上限重算
- 重排时保留样品顺序，不保留旧的手工摆放结果
- 托盘数重新压缩为满足容量的最小数量
- 重排后的托盘编号从 `TP-001` 开始重新顺排
- 新增托盘编号沿用当前任务，如 `JB-2026-101-TP-003`

若当前任务此前已经保存过托盘分配，则本次重新分配视为新方案：

- 保存新方案时覆盖旧 `tray_code`
- 删除旧的接驳分配历史，不再保留旧托盘号轨迹

### 删除托盘

删除托盘不再要求托盘为空。

删除时执行：

1. 移除目标托盘
2. 取剩余样品的顺序列表
3. 按当前统一上限重新计算最小托盘数
4. 重新顺序铺排样品

因此删除非空托盘本质上是一次安全的自动重分配操作。

但删除只在“删掉后仍能容纳全部样品”时才允许：

- 如果当前托盘数已经等于当前上限下的最小所需托盘数，则点击删除时提示“当前托盘数量已是最小值，不能继续删除。”
- 只有存在冗余托盘时，才允许删除并触发重排

这样可以避免托盘编号刷新但托盘数量不减少、同时空托盘库存被错误消耗的问题。

### 打印确认

点击“打印条形码”后仍先生成条码预览弹窗。

但打印能力增加一个前置条件：

- 当前托盘分配必须已经保存
- 未保存前，`打印条形码` 按钮保持灰色禁用态
- 已入库任务若托盘分配已保存，仍允许再次打印

### 重新入库

详情页底部第四个动作按钮文案改为 `重新入库`。

- 已入库任务点击后，仍执行原先的回退到未入库流程
- 反馈文案同步改为“任务已重新入库，已回到未入库列表”

点击弹窗里的“确认打印”时：

- 使用隐藏打印载体生成打印页
- 渲染当前任务的条码卡片
- 自动调用浏览器打印
- 打印动作发起后关闭弹窗并标记为已确认打印

此能力用于触发浏览器实际打印行为，而不是仅改变本地状态。

### 保存与确认入库

本轮将“确认入库”的前置条件改为：

- 当前任务存在有效托盘分配
- 已点击“保存托盘”

打印条码不再是入库前置条件，而是可选动作。这样接驳区可以按用户当前流程直接保存后入库。

保存成功后：

- `保存托盘` 按钮禁用
- 一旦用户调整上限、拖动样品、删除托盘或新增托盘，按钮重新恢复可点
- 已入库任务仍可打印条码，但托盘本身保持只读

## 数据与后端规则

后端托盘默认上限从 `2` 改为 `4`，并保持前后端一致。

确认入库接口不再强制校验“全部托盘已打印条码”，只校验：

- 当前任务存在待入库托盘
- 托盘中存在样品

条码字段若未生成，允许为空，不阻塞入库。

## 测试设计

### 前端运行时测试

覆盖以下行为：

- 调整统一上限后，托盘自动压缩并顺序重排
- 删除带样品托盘后，样品自动重排
- 当前托盘数已是最小值时，点击删除会显示明确提示
- 保存托盘后，无需打印即可确认入库
- 保存后按钮禁用，下一次编辑后恢复可点
- 未保存前打印按钮禁用，保存后恢复可点
- 新增托盘沿用任务内连续编号
- 已保存任务重新分配后，托盘重新从 `TP-001` 排号并覆盖旧历史
- 点击“确认打印”会触发浏览器打印接口
- 已入库任务仍可打印条码，但不能编辑托盘

### 前端结构测试

验证总览卡片与分页区具备固定布局所需的结构类与样式钩子。

### 后端 API 测试

验证：

- 待入库任务默认托盘上限为 `4`
- 未打印条码但已保存托盘的任务可以确认入库

## 验收标准

1. 总览页分页按钮在不同任务数据量下位置稳定
2. 点击“确认打印”后会触发浏览器打印动作
3. 默认托盘上限为 `4`
4. 调整上限或删除托盘后，样品按顺序自动重排到最小托盘数
5. 非空托盘可以删除
6. 当托盘数已是最小值时，点击删除会显示提示且不执行删除
7. 保存托盘后按钮变灰，且即可确认入库
8. 未保存托盘时打印按钮置灰
9. 新增托盘沿用任务编号前缀且尾号连续
10. 已保存任务重新分配后，托盘从 `TP-001` 重新编号并覆盖旧历史
11. 底部按钮文案为“重新入库”
12. 已入库任务仍可打印条码，但不能再调整托盘
