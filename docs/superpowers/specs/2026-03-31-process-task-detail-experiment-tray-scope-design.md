# 过程管控任务详情实验托盘口径设计

## 目标

修正试验过程管控页中“任务详情”弹窗的托盘口径。

当前问题是：当同一任务包含多个实验、且不同实验绑定不同托盘时，点击某个实验室打开任务详情，弹窗中的执行摘要、样品编号、当前实验托盘、待下一轮托盘等区域会显示该任务下的全部托盘，而不是当前排程实验对应的托盘。

本次修复后，任务详情弹窗里所有托盘相关区域都必须严格按当前排程记录的 `experiment_code` 过滤。

## 当前行为

- 过程管控卡片根据实验室找到对应排程
- 任务详情弹窗根据 `task_code` 聚合任务托盘
- `useProcessLabs` 已加载 `mes.experiment_trays`
- 但当前构建详情时没有用 `schedule.experiment_code` 缩小托盘集合

因此在同任务多实验场景下，弹窗会把其他实验的托盘也带进去。

## 目标行为

当用户点击某实验室的任务详情时：

- 详情使用当前实验室对应排程的 `experiment_code`
- 所有托盘相关区域只显示这个 `experiment_code` 在 `mes.experiment_trays` 中关联的托盘

适用区域：

- 执行摘要中的托盘数量与托盘芯片
- 样品编号列表
- 当前实验托盘
- 待下一轮托盘
- 默认选中的托盘及右侧统一托盘流程图

## 数据规则

### 主规则

优先按 `experiment_code + task_code` 从 `mes.experiment_trays` 中取得当前实验托盘集合。

只要当前排程存在托盘映射：

- 详情中的托盘数量 = 当前实验关联托盘数
- 样品编号列表 = 当前所选托盘中的样品
- 当前实验托盘 / 待下一轮托盘 = 在当前实验托盘集合内再按状态分组

### 回退规则

如果当前排程没有任何 `experiment_trays` 映射，则保留现有回退逻辑：

- 继续按任务聚合托盘

这样可以兼容历史旧数据，避免弹窗直接变空。

## 实现边界

只修复过程管控任务详情弹窗，不改以下模块：

- 排程页甘特与冲突分析
- 接驳区工作台
- 样品预分装页
- 任务总览页

## 设计方案

### 方案 A：在过程管控详情中引入当前实验托盘过滤

- 卡片继续沿用当前实验室和排程记录
- 构建任务详情时额外保留当前 `schedule.experiment_code`
- 托盘与样品相关辅助函数新增“可选实验托盘过滤”
- 详情只消费当前实验相关托盘

这是推荐方案，因为改动集中在 `useProcessLabs`，对现有其它模块无侵入。

### 方案 B：在模型层改卡片数据结构，提前写入过滤结果

- 让 `buildProcessLabCards` 直接输出实验托盘范围

不推荐。卡片模型本身不拥有 `experiment_trays` 数据，强行前移会让职责变乱。

## 验证要求

新增回归覆盖以下场景：

- 同任务下 A、B 实验分别绑定不同托盘
- 点击 A 实验对应实验室时：
  - 执行摘要仅显示 A 托盘
  - 样品编号仅显示 A 托盘样品
  - 待下一轮托盘仅显示 A 托盘中的未运行托盘
- 若当前实验无映射，则仍回退显示任务级托盘
