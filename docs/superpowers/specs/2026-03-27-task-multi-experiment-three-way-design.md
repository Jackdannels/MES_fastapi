# 任务多实验三分支排程与接驳区托盘选择设计

## 背景

当前系统的核心链路仍有单实验假设：

1. 一个任务默认只对应一个实验类型。
2. 排程页虽然已经开始接入实验字段，但业务语义仍容易退化为“按任务整体排程”。
3. 接驳区托盘分配与实验选择已部分拆开，但规则尚未完全固化到统一模型。
4. 不同页面对实验的展示口径不一致，有的显示实验编号，有的显示单一任务类型，有的仍残留单实验字段。

这与新的业务要求不一致：

1. 一个任务必须包含多个实验。
2. 同一份样品记录可同时参与多个实验。
3. 托盘先按任务进行分配，之后不同实验只从现有托盘中做选择，不改变托盘摆放。
4. 排程实际针对“任务下的实验”进行，但页面主线仍应以任务编号为主。

## 目标

本轮设计目标如下：

1. 建立“一个任务主线 + 三个实验支线”的统一业务模型。
2. 每个任务固定生成三个不同实验类型，供任务总览、排程、接驳区统一消费。
3. 排程最小单位升级为 `task_code + experiment_code`，但主界面仍以任务编号作为主要显示编号。
4. 接驳区默认进入任务托盘编辑态；点击实验类型后，只能选择该实验使用哪些托盘。
5. `保存托盘` 只保存当前草稿，不重置实验分配；`重新入库` 才回到初始状态并清空实验托盘分配。
6. 数据库存储、后端接口、前端模型和页面展示全部按同一口径收口。

## 业务规则

### 任务与实验

- 任务编号是主线标识。
- 每个任务必须有三个实验。
- 三个实验类型必须互不重复。
- 实验在存储层仍保留 `experiment_code`，用于排程、关联和持久化。
- 页面主展示优先显示任务编号和实验类型名称，不突出展示完整实验编号。

### 样品与实验

- 样品记录仍然是一份，不因实验拆分复制。
- 同一份样品记录可同时挂多个实验编号。
- 页面若需要显示样品参与的实验，可直接读取样品上的实验编号集合，或由任务下实验关系派生。

### 托盘与实验

- 托盘归属任务，不归属单个实验。
- 托盘布局由任务模式维护。
- 实验模式不允许调整托盘结构，只允许选择当前实验使用哪些托盘。
- 托盘卡片需要显示其已关联的实验类型标签。

### 保存与重置

- 任务模式与实验模式都先写前端草稿。
- 点击 `保存托盘` 时，一次性保存任务托盘布局与实验托盘选择。
- `保存托盘` 不重置实验分配。
- 点击 `重新入库` 时，重置：
  - 任务托盘分配
  - 实验托盘分配
  - 条码打印状态
  - 入库状态

## 数据模型

### 任务

任务主记录继续保留主线字段，并增加实验摘要辅助字段：

- `task_code`
- `status`
- `sample_count`
- `experiment_count`
- `experiment_codes`

其中 `experiment_count` 与 `experiment_codes` 只作为读视图和汇总辅助字段，真实实验数据来自实验表。

### 实验

新增或统一使用独立实验实体：

- `task_code`
- `experiment_code`
- `experiment_type`
- `status`
- `priority`

界面显示实验时，默认展示 `experiment_type`，例如：

- `温度冲击`
- `振动`
- `盐雾`

### 样品

样品记录增加：

- `experiment_codes: string[]`

表示该样品同时参与哪些实验。

### 实验托盘关系

新增实验与托盘的关系集合：

- `task_code`
- `experiment_code`
- `tray_code`

用于表示某实验选择了哪些现有托盘。

### 排程

排程记录增加：

- `experiment_code`

新排程数据必须按 `task_code + experiment_code` 持久化。

## 三实验生成规则

每个任务固定生成三个不同实验。

### 规则

1. 任务新建时，自动生成三个实验。
2. 三个实验类型必须不同。
3. 若历史任务少于三个实验，迁移时自动补齐到三个。
4. 若历史任务已存在超过三个实验，本轮不裁剪，直接保留。

### 类型池

实验类型从统一类型池中挑选，建议至少包含：

- `温度冲击`
- `振动`
- `盐雾`
- `高低温湿热`
- `耐久`
- `通电`

默认策略：

- 优先保留已有实验类型。
- 再从类型池中补足到三个不同实验类型。

## 数据库存储

### `biz_experiment`

新增或统一补齐实验主表：

- `experiment_id`
- `task_no`
- `experiment_no`
- `experiment_type`
- `experiment_status`
- `priority`
- `created_at`
- `updated_at`

### `biz_experiment_sample`

用于样品与实验的多对多关系：

- `id`
- `task_no`
- `experiment_no`
- `sample_no`

### `biz_experiment_tray`

用于实验与托盘的多对多关系：

- `id`
- `task_no`
- `experiment_no`
- `tray_no`

### `biz_schedule`

扩展：

- `experiment_no`

排程写入必须保存 `task_no + experiment_no`。

## 接口设计

### 任务接口

任务读取接口应返回：

- 任务主记录
- 该任务下全部实验
- 必要时返回样品与实验的关联结果

### 排程接口

排程读写接口必须接受并返回：

- `task_code`
- `experiment_code`

页面显示时再映射为：

- 主显示：任务编号
- 实验显示：实验类型

### 接驳区接口

接驳区 bootstrap / workspace 至少返回：

- `task`
- `experiments`
- `samples`
- `trays`
- `experimentTrays`

接驳区保存接口统一接收：

- 任务托盘草稿
- 实验托盘选择草稿

接驳区重新入库接口统一清空：

- 任务托盘分配
- 实验托盘分配
- 条码打印和入库状态

## 页面设计

### 任务总览与任务受理

- 任务仍按任务编号显示。
- 实验摘要显示三个实验类型，例如：
  `温度冲击 / 振动 / 盐雾`
- 实验数显示总个数，例如 `3`。
- 不再把单一任务类型误当成实验信息。

### 排程页

- 手动排程和排程列表主显示任务编号。
- 实验选择下拉显示实验类型。
- 完整实验编号只用于内部关联和必要的追溯，不作为主显示字段。
- 同一任务下三个实验可分别排到不同设备、不同时间。

### 接驳区

- 默认进入任务托盘编辑态。
- 第一层只显示任务编号。
- 第二层显示该任务下三个实验类型。
- 点击实验类型后进入该实验的托盘选择态。
- 实验态下托盘只支持勾选选择，不允许改托盘结构。
- 托盘卡片显示实验类型标签，不显示 `A实验/B实验` 文案。

## 测试范围

### 模型

1. 一个任务默认生成三个不同实验。
2. 同一份样品可挂多个实验编号。
3. 一个实验可关联多个托盘。

### 排程

1. 同一任务下三个实验可独立排程。
2. 排程持久化保留 `task_code + experiment_code`。
3. 页面主显示仍为任务编号，实验显示为实验类型。

### 接驳区

1. 默认进入任务托盘模式。
2. 点击实验类型进入实验模式。
3. 实验模式仅可选择托盘，不可改托盘结构。
4. `保存托盘` 后保留实验分配。
5. `重新入库` 后清空实验分配并回到初始状态。

### 数据库与接口

1. `biz_experiment` 可正确写入和回读。
2. `biz_experiment_sample` 可正确写入和回读。
3. `biz_experiment_tray` 可正确写入和回读。
4. `biz_schedule.experiment_no` 可正确持久化。
5. 任务、排程、接驳区三个入口读取到的实验列表保持一致。

## 成功标准

1. 每个任务默认都有三个不同实验。
2. 任务总览、任务受理、排程页、接驳区看到的实验列表一致。
3. 排程按实验进行，但界面主线仍清晰显示任务编号。
4. 接驳区托盘布局只由任务模式维护；实验模式只选择托盘。
5. `保存托盘` 不重置实验分配；`重新入库` 才重置。
6. 数据库存储与前端展示不再混用单实验旧语义。
