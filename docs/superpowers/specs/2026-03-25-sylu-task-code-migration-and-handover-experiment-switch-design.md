# SYLU 任务编号迁移与接驳区实验切换设计

## 背景

当前系统虽然已经引入“一个任务包含多个实验”的基础模型，但仍存在三类不一致：

1. 老任务没有完整的 `mes.experiments` 数据时，只能走“默认补一个 A 实验”的兼容逻辑，导致像 `GDW-2024-005` 这类历史多实验任务在排程页只显示一个实验。
2. 任务编号仍混用 `CJ / GDW / MJ / SZH / WDC / ZD / YW` 这类前缀格式，且样品、托盘、实验、排程、数据流的关联编号都依赖旧任务号。
3. 接驳区虽然已有实验级托盘分配能力，但任务详情头部没有把“任务编号主线 + 实验支线”的结构表达清楚，实验切换入口位置和交互也不符合最新业务要求。

新的业务要求是：

1. 任务编号统一迁移为 `SYLU-YYYY-MM-NNN`
2. 实验编号作为任务支线，格式为 `SYLU-YYYY-MM-NNN-A / B / C`
3. 所有关联编号保持一致，自动迁移旧快照与旧数据库记录
4. 排程页必须为历史多实验任务显示完整实验列表，不再错误回退为单实验
5. 接驳区详情默认进入任务托盘编辑态，头部第一层只显示任务编号，第二层只显示实验类型；点击实验类型切换到实验托盘选择态，点击任务编号或空白处返回默认编辑态

## 目标

本轮设计目标：

1. 建立统一、幂等的编号迁移机制，将旧任务与全部关联实体迁移到 `SYLU` 编号体系
2. 为历史多实验任务补齐正式实验记录，确保排程、总览、接驳区读取到一致的实验列表
3. 将实验展示语义从 `A实验 / B实验` 切换为真实实验类型名称，完整实验编号仅用于悬停和内部引用
4. 调整接驳区头部与交互，突出“任务主线 + 实验支线”并符合默认编辑、显式选择实验、任务编号/空白处返回的操作方式

## 非目标

本轮不做：

- 不更改“一个任务下多个实验”的核心关系模型
- 不把条码编码内容改为实验编号，条码主值仍只使用托盘编号
- 不新建额外的“任务托盘”按钮或特殊组件形态，仍沿用当前页面样式语言
- 不引入人工手动迁移脚本作为主要路径，迁移应由系统自动完成

## 编号规则

### 任务编号

- 格式：`SYLU-YYYY-MM-NNN`
- 示例：`SYLU-2026-03-001`
- `NNN` 按任务在该月内递增
- 任务编号不包含实验信息，只表示任务主线

### 实验编号

- 格式：`<task_code>-A / B / C`
- 示例：
  - `SYLU-2026-03-001-A`
  - `SYLU-2026-03-001-B`
- 实验编号表示任务下的支线，不单独生成新的主任务号

### 样品与托盘编号

- 样品编号：`<task_code>-SP-001`
- 托盘编号：`<task_code>-TP-001`

示例：

- `SYLU-2026-03-001-SP-001`
- `SYLU-2026-03-001-TP-001`

所有依赖任务号的下游数据都必须同步改写为新任务号，不能出现任务号迁了但样品、托盘、实验或排程仍引用旧号的情况。

## 自动迁移设计

### 迁移入口

迁移分两层执行：

1. 读时迁移
   - 前端快照读取与后端 storage load 时先做规范化
   - 保证页面和接口永远消费迁移后的新模型
2. 写时固化
   - 保存回 JSON / MySQL 时写入新编号和补齐后的实验结构
   - 避免每次加载都重复迁移同一批旧数据

### 迁移版本标记

建议增加全局版本标记：

- `mes.meta.schema_version = 2`

规则：

- 无版本标记时执行迁移
- 已为 `schema_version = 2` 时跳过迁移
- 迁移逻辑必须幂等，重复执行不会二次改号或重复补实验

### 迁移排序与重编号规则

任务重编号建议按以下顺序稳定排序：

1. `arrival_at`
2. `created_at`
3. 旧 `task.code`

然后按月份分组，对每个月生成：

- `SYLU-YYYY-MM-001`
- `SYLU-YYYY-MM-002`
- `SYLU-YYYY-MM-003`

这样可以保证：

- 同月任务序号可解释
- 重复迁移不会改变同一批数据的结果
- 新老数据合并时不会因为旧前缀不同而破坏排序

### 迁移覆盖范围

迁移必须覆盖以下字段：

- `mes.tasks.code`
- `mes.tasks.experiment_codes`
- `mes.samples.code`
- `mes.samples.task_code`
- `mes.samples.trays[*].tray_code`
- `mes.samples.trays[*].sample_code`
- `mes.experiments.task_code`
- `mes.experiments.experiment_code`
- `mes.experiment_trays.task_code`
- `mes.experiment_trays.experiment_code`
- `mes.experiment_trays.tray_code`
- `mes.schedules.task_code`
- `mes.schedules.experiment_code`
- `mes.streams.task_code`
- 接驳区 workspace / 条码打印 / 托盘标签等所有运行时派生视图

MySQL 侧需要同步覆盖：

- `biz_task.task_no`
- `biz_experiment.task_no / experiment_no`
- `biz_experiment_tray.task_no / experiment_no / tray_no`
- `biz_schedule.task_no / experiment_no`
- 流记录对应的 `task_no`

## 历史多实验任务补齐规则

### 基本规则

老任务补实验时按以下优先级处理：

1. 若已有显式 `experiments`
   - 保留原实验数量与顺序，只重写编号和显示名称
2. 若任务已有 `experiment_count > 1` 或 `experiment_codes`
   - 按已有数量补齐完整实验记录
3. 若任务属于业务定义的历史多实验任务
   - 在迁移规则中补成正式实验记录
4. 其他旧单实验任务
   - 才补默认唯一实验

### `GDW-2024-005` 处理

`GDW-2024-005` 不能继续走“默认单实验”兼容逻辑。

迁移后它应被补齐成正式的双实验任务：

- 新任务号：`SYLU-2026-03-00X`
- 实验号：
  - `SYLU-2026-03-00X-A`
  - `SYLU-2026-03-00X-B`

并在 `mes.experiments` / `biz_experiment` 中形成两条正式记录。这样排程页、任务总览和接驳区都会自然显示两个实验，而不是各模块各自再写一层特判。

### 实验显示名称

实验项在界面上的显示，不再使用 `A实验 / B实验` 作为正文。

展示规则改为：

- 正文显示真实实验类型名称，例如：
  - `高低温湿热试验`
  - `振动试验`
  - `盐雾试验`
- 完整实验编号仅用于：
  - 悬停 `title`
  - 副标题
  - 内部保存与接口传输

也就是说，`-A / -B / -C` 只承担内部支线编号职责，不承担页面主展示职责。

## 排程页设计

### 任务与实验选择

排程页手动排程区域继续保留：

- 任务编号下拉
- 实验编号下拉
- 实验室
- 日期
- 时段
- 预计实验时长

但其含义调整为：

- 任务下拉显示新任务号，例如 `SYLU-2026-03-001`
- 实验下拉正文显示真实实验类型名称
- 下拉项悬停或附加文本显示完整实验编号，例如 `SYLU-2026-03-001-A`

对于没有显式实验记录的老任务，不再只补一个默认实验，而是先经过迁移层补齐正式实验列表。

### 排程对象

排程最小单位仍是：

- `task_code + experiment_code`

其中：

- `task_code` 指向新任务号
- `experiment_code` 指向支线实验编号
- 页面显示则以实验类型为主

## 接驳区设计

### 头部结构

任务详情头部改成两层：

1. 第一层
   - 只显示任务编号，例如 `SYLU-2026-03-001`
   - 不显示摘要、副标题或“任务托盘”字样
2. 第二层
   - 直接显示该任务下的所有实验类型
   - 例如：
     - `高低温湿热试验`
     - `振动试验`
     - `盐雾试验`

第二层既是实验切换入口，也是任务摘要信息，不再额外重复展示摘要文字。

### 默认态与实验态

进入任务详情后：

- 默认即为任务托盘编辑态
- 不需要额外点击任何“任务托盘”按钮来开启编辑

当用户点击第二层某个实验类型时：

- 切换到该实验的托盘选择态
- 任务托盘布局保持不变
- 只允许选择该实验使用哪些托盘

### 返回默认编辑态

从实验态返回默认任务托盘编辑态的触发方式：

1. 点击第一层任务编号
2. 点击头部或详情页空白处，取消当前实验选中

不新增单独的“返回任务托盘”按钮。

### 第二层展示规则

第二层不使用 `A实验 / B实验` 文案，直接展示实验类型名称。

示例：

- `高低温湿热试验`
- `振动试验`

其内部仍对应：

- `SYLU-2026-03-001-A`
- `SYLU-2026-03-001-B`

悬停可显示完整实验编号。

### 托盘选择规则

现有多实验托盘分配规则保持：

- 默认态允许编辑托盘结构
- 实验态只允许选择托盘，不允许改变托盘内样品摆放
- 若任务托盘结构发生真实变更，原实验托盘草稿与持久化绑定应被清空并要求重新分配

## 数据库与存储影响

### JSON

需要迁移和补齐：

- `mes.tasks`
- `mes.samples`
- `mes.experiments`
- `mes.experiment_trays`
- `mes.schedules`
- `mes.streams`
- `mes.meta`

### MySQL

需要支持：

- 旧任务号到新任务号的统一迁移
- `biz_experiment` 与 `biz_experiment_tray` 的正式读写
- `biz_schedule.experiment_no` 全量补齐
- 旧记录按迁移规则补实验并回写

建议将迁移逻辑集中在存储层，而不是散落在各 API route 或各页面 model 中。

## 验证目标

1. 老数据首次读取后，全部任务与关联实体迁移到 `SYLU` 编号且引用一致
2. `GDW-2024-005` 迁移后在排程页显示两个实验
3. 新建任务自动生成 `SYLU-YYYY-MM-NNN`
4. 样品、托盘、实验、排程、数据流都引用迁移后的同一主编号
5. 排程页实验下拉正文显示实验类型，完整实验编号可追溯

8. 点击实验类型可切换实验托盘选择态
