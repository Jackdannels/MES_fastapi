# 盐雾试验室操作台设计

## 目标
在当前前端项目中新增一个独立模块 `laboratory`，以“盐雾试验室操作台”作为独立界面进入，页面结构参考 `laboratory.zip`，但业务字段、状态口径、模块边界和导航方式全部以现有项目为准。

## 模块边界
- 新模块键：`laboratory`
- 独立模块名称：`盐雾试验室操作台`
- 模块首页路由：`/laboratory`
- 模块归属：与 `central`、`handover`、`visual`、`staging` 并列的一级模块
- 页面范围：第一版只包含一个主页面，不做多实验室切换

## 接入原则
- `laboratory.zip` 仅作为页面布局、交互组织和样式参考
- 与当前项目不一致的内容一律以当前项目为准
- 不为该模块单独增加后端接口
- 不引入第二套本地存储结构
- 不改动现有中控、接驳区、暂存间模块的业务规则

## 数据来源
页面复用现有本地/远端快照体系，优先从以下存储键读取：
- `mes.tasks`
- `mes.schedules`
- `mes.experiments`
- `mes.experiment_trays`
- `mes.samples`

页面只保留与 `盐雾试验室` 相关的数据。核心判断规则：
- 当前实验室任务列表：`schedule.device === "盐雾试验室"`
- 当前任务：优先取正在执行中的盐雾试验室排程；若无，则取最近的未来排程
- 实验名称：优先从 `experiments` 通过 `task_code + experiment_code` 匹配
- 托盘/样品信息：优先复用现有样品与实验托盘映射口径

## 页面结构
页面保留 zip 中的三层结构，但数据改为真实项目口径：

1. 顶部摘要卡
- 今日实验排程数量
- 今日未做实验数量

2. 操作台卡片
- 查看当前实验室任务
- 任务比对
- 样品安装
- 实验确认

3. 流程状态区
- 当前任务编号 / 实验名称
- 当前流程提示

4. 弹窗
- 实验排程清单
- 当前实验室任务清单
- 任务比对确认
- 样品安装确认
- 实验确认 / 已确认提示

## 行为规则
- 页面默认只服务 `盐雾试验室`
- “查看排程”按钮继续以页头 Teleport 方式放到头部操作区
- 比对、安装、确认三个动作采用前端工作流门禁
- 第一期不把这三个动作持久化回任务/样品正式状态，只用于操作台流程引导
- 页面刷新时工作流重置，但任务数据仍来自存储快照

## 第二期细化交互

### 最近安排任务区
- 在操作卡片下方增加“最近安排任务”区域
- 仅显示 `盐雾试验室` 的最近排程
- 每条记录显示：
  - 任务编号
  - 实验名称
  - 排程开始时间
  - 排程结束时间
  - 当前是否为已选任务

### 查看任务弹窗
- 从简单清单升级为详细任务表
- 每条记录额外显示：
  - 开始时间
  - 结束时间
  - 托盘列表
- 托盘改为逐行显示，不再合并成单个摘要字符串
- 支持“选择任务”并“确认当前任务”

### 当前任务选择规则
- 若用户未手动选择任务，则默认当前任务为：
  - 正在执行中的盐雾试验室排程
  - 若无正在执行中的排程，则取最近未来排程
- 一旦用户在“查看任务”弹窗中确认其他任务，该任务成为当前任务
- 比对、安装、确认流程均绑定当前已选任务

### 扫码比对
- “任务比对”弹窗改为扫码确认面板
- 扫码对象为托盘号
- 只有命中“当前任务 + 当前实验”的托盘，才判定为比对正确
- 正确时显示绿灯/绿色反馈与“比对正确”
- 错误时显示红灯/红色反馈与“比对不正确”
- 若该托盘属于其他已知排程，则额外提示：
  - 拒绝原因为“当前任务并非优先所选任务”
  - 该托盘当前可前往的全部实验室列表
  - 若同一托盘同时绑定多个实验，提示需聚合全部可去实验室，而不是只取第一条命中排程
- 若无法匹配任何任务，则提示“未匹配到该托盘”
- 未进行任务选择时，系统按默认当前任务规则比对，因此后续任务托盘会被拒绝

## 第三期流程持久化

### 实验室三步状态写回
- 操作台三步不再只是前端临时门禁，而是写回现有 `mes.samples` 快照
- 状态口径：
  - 任务比对完成：托盘状态同步为 `已到达实验室`
  - 样品安装完成：托盘状态同步为 `工装夹具安装`
  - 实验确认完成：托盘状态同步为 `实验准备就绪`
- 页面刷新后，当前任务流程进度需要根据已保存的托盘状态自动恢复
- 为避免把“样品当前位置”误判成已完成步骤，实验室操作台的流程门禁优先以当前任务托盘状态反推

### 实验开始口径
- `盐雾试验室操作台` 的第 3 步仅表示“确认实验准备就绪”，不会直接把任务判定为 `实验中`
- 全项目的 `实验中` 判定统一为：只有在 `试验过程管控` 中点击 `开始实验` 后，托盘状态进入 `实验进行中`，任务才进入 `实验中`
- `送至实验室`、`已到达实验室`、`工装夹具安装`、`实验准备就绪` 都属于实验前准备链路，不能单独把任务推进到 `实验中`
- 排程时间窗口只能说明任务“已排程”，不能自动说明实验已经开始

### 最近安排任务卡片
- 最近安排任务卡片改为居中展示
- 任务编号作为主标题放大显示
- 实验名和时间信息一并放大
- 时间显示完整日期与时间，而不是仅显示时分

## 第四期联动刷新与双栏流程

### 中控托盘管理实时刷新
- 盐雾试验室操作台执行 `任务比对 / 样品安装 / 实验确认` 后，除写回 `mes.samples` 外，还需要派发 `mes:samples-updated`
- 中控系统托盘管理已监听该事件，因此托盘状态与流程图应立即刷新，不再依赖手动刷新

### 查看任务弹窗放大型单行布局
- “查看任务”弹窗放大显示，每个任务占一整行
- 每行固定展示：
  - 任务编号
  - 实验名
  - 开始时间
  - 结束时间
  - 当前实验的托盘列表
  - 选择任务按钮
- 托盘信息横向展示在同一行中
- 当前已选任务需要整行高亮，不只在按钮位置显示“已选中”
- 当前任务与未选任务在边框、底色和标签上都要有明显区分

### 下方流程状态区改为左右双栏
- 左侧显示“任务流程图”
- 右侧显示“托盘流程图”
- 右侧上方增加当前任务当前实验的托盘切换条
- 允许在同一实验的不同托盘之间切换，切换后右侧流程图即时更新

### 任务流程口径
- 左侧任务流程严格复用中控系统任务流程图的聚合口径，不按“当前实验”单独聚合
- 若任务下任意实验的任意托盘进入活动实验链路：
  - `送至实验室`
  - `已到达实验室`
  - `工装夹具安装`
  - `实验准备就绪`
  - `实验进行中`
  - `实验中`
  则该任务显示为 `实验中`
- 若任务下所有实验、所有托盘都进入：
  - `实验已完成`
  - `实验完成`
  - `放置实验后暂存间`
  - `厂家收回`
  则该任务显示为 `实验已经完成`
- 只有所有托盘都为 `厂家收回` 时，任务才显示为 `厂家收回`

### 托盘流程口径
- 右侧托盘流程仅显示“当前任务 + 当前实验 + 当前选中托盘”的状态
- 当前任务切换时，托盘切换条同步切换到新任务当前实验的托盘集合，默认选中第一个托盘

## 兼容实现
- 模块级入口接入点：
  - `frontend/src/lib/moduleCatalog.js`

  - `frontend/src/modules/index.js`
  - `frontend/src/modules/login/page.vue`
- 页面级实现：
  - 新增 `frontend/src/modules/laboratory/`
  - 新增独立 `index.js / page.vue / styles.css / model.js / useLaboratoryPage.js`
- 测试：
  - 模块注册结构测试
  - 认证/模块首页映射测试
  - 页面模型测试
  - 页面运行时测试

## 风险
- zip 中任务模型是演示假数据，不能直接进入现有项目
- 现有样品、托盘、排程字段存在多来源回退逻辑，需要在新模块内部单独做适配
- 独立模块接入会影响登录和模块切换路径，需要覆盖这部分测试
