# 三套专用客户端本机测试

日期：2026-11-07；客户端版本：1.1.0。

## 范围

本轮完成中控、LIMS 和上位机模拟器的独立 WebView2 EXE，以及控制中心对三套客户端的打开、关闭和重启管理。没有迁移、覆盖或停止正在使用的系统。

## 实现

- 一套 C# 内核，三个固定编译角色、不同 EXE 名称和页面标题。
- 每个角色独立单实例锁、用户数据目录、下载目录和本机命令通道。
- 默认全屏、原生退出和刷新入口，不显示浏览器地址、收藏与标签栏。
- 控制中心根据三个服务地址打开对应 EXE；关闭会尝试处理全部窗口并汇总错误。
- 主动退出停用恢复计时器，等待主进程退出；不会按 Edge/WebView2 进程名称批量结束进程。
- 增加只读诊断计数：页面脚本错误、API 成功响应和失败响应。

## 隔离方法

LIMS 与上位机使用原有 FastAPI 应用，在本机临时端口运行。LIMS 序号、回执等数据使用临时 SQLite 文件；两者关闭服务 lifespan，保持消息队列未连接。测试没有发送真实任务或实验事件。

中控的本机生命周期测试使用隔离 HTTP 页面。控制中心的启动/关闭/重启使用测试控制脚本，其服务状态返回值用于驱动真实客户端窗口；本轮没有执行真实 MES 服务停止或重启。

## 测试

结果：客户端与三窗口集成共 **21 项通过**；现有桌面工具与两个模拟器回归共 **72 项通过**；旧浏览器管理专项通过。

- `tests/core/test_desktop_client.py`：原有客户端生命周期、全屏、角色注入、站外跳转阻止、故障恢复。
- `tests/core/test_desktop_simulator_clients.py`：真实模拟器页面与 API 轮询、角色配置不匹配、三个角色身份隔离、三窗口启动/重复启动/失败停止/重启/重建管理对象后关闭、独立实例不受影响。
- `tests/core/test_desktop_docker_tools.py`：既有桌面工具与服务脚本回归。
- `tests/tools/test_lims_simulator.py tests/tools/test_upper_simulator.py`：现有模拟器行为回归。
- `tests/control_center/Test-ControlCenterBrowser.ps1`：原浏览器入口与普通窗口隔离回归。

本轮未修改前端网页业务、后端共享工作流、MQTT 事件规则或高低温湿热二室的本地夹具例外，因此未重复运行未变动侧的完整测试。

## 后续使用

本机构建出的 EXE 可在各自 `mes-client.json` 中指定本机服务地址后单独运行。页面服务仍由原有 Python/前端服务提供，EXE 不包含服务端。其他电脑安装、开机启动、IP/工位分发按当前指示暂不执行。
